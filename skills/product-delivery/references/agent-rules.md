# Agent 行为红线（product-delivery）

编码分层红线见 [`layered-codebase`](../../layered-codebase/SKILL.md) 的 `references/agent-rules.md`。本文只约束**需求澄清、文档寿命与闸门**。

## 必须先问再做

- 判不准 S/M/L，或 explore 后改动面与口头不一致
- 改 `product/` 宪法或 `architecture/spine` 扩展点
- 把某次变更升/降档
- 新建顶层文档约定（改 `docs/` 根结构）且仓库尚未约定
- 删除或大幅改写未 Frozen 但用户已确认过的 Demo/契约（先确认）
- 指代不清：合并到哪条分支、skill 权威路径放哪、本地进程是否同源托管 UI。禁止擅自选更常见默认（例如并进 main、只写某一工具目录、把开发热更双端口写成产品终态）
- 目标 Agent 宿主实际能力未知，却要设计监听 / 推送 / 进度通道

## 确定性禁止

- 闸门未过写业务实现，或「先跑一版再对齐」
- 把「嗯 / 看看 / 差不多」当成确认
- 回写 Frozen 变更包正文「保持同步」
- 推荐用户读历史变更包当现行产品说明
- Grill 一次抛长问卷
- 未读 layered-codebase 就在编码阶段堆业务分层
- 对外契约已变却不更新现行契约/生成物
- 长期行为图只留在 Frozen 包、不提升 `architecture/`
- 把交互 Demo 当视觉规格，或把控件清单拷进成品
- 把演示专用控件（顶栏已能导航仍加的跳转按钮等）默认带进产品
- Grill / 体验闸不拿用户差异化句子回检，默认套竞品/旧品类模板（关卡式流程、缺产物锁死导航、照搬其按钮文案）
- 角色未钉就写长协议；或默认 Agent 经 HTTP 调本机服务、直连第三方、自己充当执行器报进度
- 先发明未经验证的通信开关 / 推送通道 / 「禁止某调用」类协议字段，再问宿主能不能做到
- 契约写 `null` 键、无用 API、把运行时快照（如 pid、端口）塞进配置文档、为以后扩展堆字段
- 代码包拆了就默认运行时多进程；本地工具把开发热更双端口写成产品终态（默认一个进程同源托管 UI+API；热更前端仅可选）
- 主代理犹豫后把 L 整页 Demo 留在主会话（明文：默认派）

## 文档与措辞

- 区分：**已确认** / **建议** / **待确认**
- 不把推测写成用户已确认的事实
- 代码与活文档冲突：改活文档对齐代码，并告知用户
- CHANGELOG 只记用户可见或对外契约变化（见 [`doc-model.md`](doc-model.md)）
- 契约短。可丢：重复、废稿、架构空谈、实现猜测。不可丢：数据形状、错误码、HTTP/CLI/磁盘/WS/退出码
- 配置 vs 运行快照、全局配置 vs 工程目录、可复用参数档与单次覆盖等概念分开写
- 精简后担心丢信息：子代理只审「外部可感知缺口」，不靠把文档写长

## 编排

- 主会话只留决策与指针；长产出（整页 Demo、explore 报告、契约起草、领域 design、实现切片）在 **L 默认派**子代理（例外见主 SKILL 编排表）
- 「可派」不得读成爱派不派；L 整页 Demo 堆主会话算偏离默认编排
- 不为「显得规范」事事派（交接本身变 noise）；S/小补丁不硬派
- 子代理 prompt 必须含：目标、约束、路径、已确认结论、禁止事项、交回格式（短报告 + 路径）
- 不依赖子代理再套娃派子代理；由主会话按回传再派
- 对用户回复 Demo 结果时给路径与怎么点，不粘贴整页 HTML
- 派 Demo 的 prompt 写明：交互确认，非视觉源；「仅演示」控件单列

## 交付回复最低要求

- L/M：验收依据（脚本步骤或勾选结果），不能只说「做完了」
- 动码：附 layered-codebase 要求的验证证据（命令与结果）
- 列出更新过的活文档路径；Frozen 包路径（若有）
- 体验已过、写码前：契约已再审「写码会猜错的可感知项」
- 产品承诺交付 Agent SKILL：回复里给出权威路径（及可选镜像）
