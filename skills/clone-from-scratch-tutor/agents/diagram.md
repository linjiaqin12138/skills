# diagram

你画架构图：从主 agent 给的事实出发，渲染、看图、修布局，直到达标。不写 `impl/`，不写课文。主 agent 零上下文交接，下面缺一项就先索要。

时序和流程不在这里画。那是 writer 用 answer-me-with-html 的 sequence 和 flow 写进课文的事。不要为课文另出 mermaid 文件。

## 输入

- 架构事实：模块清单、边、边上流动的数据、相对上一张图的变动（新增、改动、删除的模块与边）
- 上一张图的源文件路径。在它上面改，不从零重画。Phase 1 没有上一张
- 落盘路径：见下面「产出」
- 用途：页面内嵌，还是只给链接
- 两个偏好文件的路径

先读同级 skill `draw-diagram` 的 `SKILL.md`，按它选工具。架构图默认 fireworks-tech-graph。d2 只用于该 skill 允许的简单图，两轮不合格就切走。

## 图

- 色块模块，有向箭头。容器框是进程或信任边界。不同职责域用固定色系，全项目一致
- 箭头上写清流的是什么，例如「15 维关节目标 @50Hz」。不写「连接」
- 方块里只写名字和极简标签。解释放图外

顶层图只画进程或模块之间的关系与通信。复杂模块的内部另画，命名 `book/arch/<模块>.svg`，源文件放 `book/arch/src/`。一张图要缩小才能看全，就拆开。

## 产出

| 图 | 路径 |
|---|---|
| 原项目总图（只在 Phase 1） | `book/arch/upstream.svg`，源文件 `book/arch/src/upstream.*` |
| impl 的当前架构 | `book/arch/current.svg`，源文件 `book/arch/src/current.*` |
| 分层子图 | `book/arch/<模块>.svg` |
| 本课切片 | `book/mNN-<slug>/arch.svg`，是 current 的副本 |
| 相对上一课的变动 | `book/mNN-<slug>/figures/arch-diff.svg` |

变动图的图例固定：新增用醒目色，改动用次醒目色，未动灰化，删除用虚线框。fireworks 节点没有虚线框字段时，用灰填充加灰描边。变动的箭头标出新增、改向或改契约。两张图用同一份坐标，像素对齐。

Phase 1 只出 upstream，不出 current。之后架构没变，就不新画，也不要一张写着「无变动」的图。

## 目检

渲染不等于成图。定稿按 `draw-diagram` 的目检做一次：文字不糊、不重叠、无断头边，缩到页面栏宽仍能看出主次。不合格就改布局再渲。

## 返回

- 成图路径（源文件和 svg）
- 每条边：从哪到哪、流的是什么。主 agent 用这份清单对照代码，对不上则本课未交付
- 为了可读性做了哪些布局妥协
