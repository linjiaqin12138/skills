# Phase 2 · 里程碑

按依赖树排 `m01`…。每个里程碑写进 `tutor/phases/phase-2.md`，含五项：目标一句话、前置依赖、验收标准、预计工作量、相对原版的简化项以及预定在哪一课收敛。

里程碑只排本课验收要用的实现。不为后面的课预埋结构。

单里程碑上限：新概念 ≤ 2，代码领读模块 ≤ 5，决定 ≤ 3。超出就拆成下一个编号；需要并排时用 `m02a`、`m02b` 这种带字母的后缀。

标明哪些数据或服务直接下载，手搓范围只限 `impl/` 里的代码。实现语言默认跟随上游，用户明确要求才换。

## 覆盖

`spec/features.md` 里每个复刻项必须映射到某个里程碑的验收标准。本阶段末尾附一张表：清单项 → 里程碑号。映射不上的项，或者排进某个里程碑，或者改成豁免并重新请用户确认。不允许既没排期也没豁免。

把映射回填到清单的「处置」列。

## 先修能力评估

按里程碑的真实任务列能力，不只列术语。例如「从空白文件搭建带关节与执行器的仿真模型」比「MJCF」更可判断。每个能力配一句项目任务，随里程碑计划询问用户经验：能独立做 / 能看懂修改 / 完全没接触。能从既有偏好或已完成练习确认的，不重复问。

对缺少的经验，让用户选路线：直接实现 / 项目内引导 / 先修学习。可依据盲区范围建议，不把不熟一律强制送补课。结果记入 `tutor/user-prefs.md` 的先修能力表：能力、项目任务、经验、路线、出口标准、状态、先修记录路径。

- **直接实现**：AI 写项目代码，用户通过代码领读学习。已熟概念在课文里至多一句。
- **项目内引导**：安排小练习与项目实现交替。不熟概念按理解所需给正文最小解释；必要概念过多时优先拆分或调序，不用概念页链接代替讲解。
- **先修学习**：若是该里程碑的关键前置，先建 `tutor/prerequisites/<slug>.md` 和可观察的出口标准，按 [prerequisite.md](prerequisite.md) 执行；未完成前 Phase 3 不启动对应 coder。

只有不阻塞项目实操的概念缺口，才按旧方式在 Phase 3 调度 concept-writer 补材料。用户中途说看不懂时随时补标并重估路线。

更新 `tutor/STATE.md`。列出尚未从代码确认的推断。停下，等用户说继续。
