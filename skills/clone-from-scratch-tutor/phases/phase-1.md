# Phase 1 · 自顶向下拆解

做完停下，等用户批准功能清单。未批准不进入 Phase 2。

## 原项目模块图

按 [agents/diagram.md](../agents/diagram.md) 画原项目的模块图，落盘：

- 源文件：`book/arch/src/upstream.*`
- 图：`book/arch/upstream.svg`

每个模块配四行字：职责、输入、输出、接口契约。`impl/` 还没有架构，这一阶段不写 `book/arch/current.svg`。

## 原作者的关键决定

挑 3 到 5 个最关键的架构决定。每个写成一篇 `decisions/NNNN-<slug>.md`，从 `templates/decision.md` 复制。来源填「原项目」，状态先填「起草」。用户批准本阶段后改为「已记录」。

## 词表

用户级偏好里有主力栈时，在 `tutor/phases/phase-1.md` 加一张表：原项目的词、用户已经有的词、两者的差异。没有主力栈就省略。这张表不写进课文。

## 功能清单

填写 `spec/features.md`。这是范围宪法。逐层枚举原项目的全部对外表面：每个进程或 daemon、每个 RPC 方法与 CLI 子命令、每个配置参数、每个事件或通知及其载荷字段、每个持久化产物。RPC、CLI、配置从定义文件逐项抄，不凭印象列。

每一行：`功能项 | 证据（文件:行号）| 处置 | 交付`。处置只写两种：`复刻 → mNN`，或 `豁免 → 理由`。这一阶段里程碑还没排，复刻项的里程碑可先空着，Phase 2 补上。

列完后把清单交给用户逐段确认：哪些豁免同意，哪些改回复刻。用户批准后，把模板里的「用户批准」改成已批准和日期。之后范围变更只走改清单加用户确认。

发现读不到的证据，标【合理推断】，并在阶段结束时单独列出。更新 `tutor/STATE.md`。停下。
