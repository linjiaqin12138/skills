# 先修学习 · 能力路由与家教交接

用于 Phase 2 选定先修学习，或 Phase 3 发现关键前置缺失时。目标不是另开一门完整课程，而是让用户获得完成当前项目任务所需的最低实操能力，再回原 Bite。

## 三条学习路线

- **直接实现**：用户能独立做，或确认看代码就能学会。AI 实现，用户读代码、决定与验收。
- **项目内引导**：用户有基础，只缺项目特定知识。小练习与项目实现交替，不阻塞无关 Bite。
- **先修学习**：用户缺少整个领域的基础工作流程，直接读实现会困惑。暂停相关项目 Bite，先完成针对性练习。

不熟不等于必须先修。询问经验后由用户选择；可建议，不强制。用户可改选、跳过或随时返回项目，把选择记入 `tutor/user-prefs.md` 与先修记录，不重复劝说。

## 内部记录

每个先修主题建 `tutor/prerequisites/<slug>.md`，练习放 `exercises/<slug>/`。练习不是正式项目实现，不放 `impl/`，不计入功能清单。

先修记录包含：

1. **调度与 audit（内部）**：触发证据、项目任务、用户经验、所选路线、需要的能力、刻意不覆盖的内容、教材与家教选择依据、出口标准、返回位置。
2. **实时交接**：当前练习、已完成动作、当前卡点、已经有效的提示、下一动作、等待谁回应。
3. **练习证据**：用户亲自做的修改、运行结果、预测或回讲；区分用户完成与 AI 验证。
4. **返回摘要**：已掌握能力、仍需提醒的误区、是否达到出口、返回哪个里程碑 / Bite。

每轮结束更新实时交接。auto compact 只作兜底，不能充当进度存储。返回项目后补记读者能否顺利继续，供后续调整路线。

这些记录不进入 `book/`，不渲染进课文，也不复制到项目 README。给 writer 的只有返回摘要，不是整份记录。

## 会话形式

短补（一个概念或 1–2 个短实验）可留在当前会话。多轮先修默认新开会话，避免项目实现与家教互相干扰；用户明确想留原会话时尊重选择。

项目会话暂停在返回位置，给用户一句启动提示：

> 新开会话后，在项目根目录发送「按 tutor/prerequisites/<slug>.md 继续家教，从当前进度开始」。

家教会话只加载用户偏好、先修记录、当前练习与家教 skill，不重读整段项目历史。主 agent 直接与用户多轮互动，不用一次性 subagent 代替家教。结束或换会话时以磁盘记录续作，不依赖旧对话仍在上下文里。

## 家教与教材

优先选覆盖当前能力的官方或成熟教程。互动家教骨架默认用 `learn-coach`，叠加本文件的终端实验闭环；`concept-writer` 负责概念材料，`explain-it` 负责具体卡点，两者都不冒充完整先修家教。

没有可用的 `learn-coach` 时，明确告诉用户缺什么并询问是否安装或改选，不假装调用成功，不静默换成只读课文。教材、家教名称与版本写进内部记录。

## 每轮怎么教

一轮只推进一个动作或一个问题，然后停下等用户：

1. 让用户预测、补少量关键内容或做一次修改。
2. 给当前一步必需的命令，让用户亲手运行并反馈现象或输出。
3. 根据回应继续、缩小提示或重做一个实验。

AI 可预先维护参考解答与验收，用来判断结果，但不提前展示完整答案，不用 AI 跑通代替用户完成。样板与配置可由 AI 写，涉及核心能力的部分留给用户。连续两次无提示完成后撤架；持续卡壳时增加脚手架。

用户说「直接告诉我」就直接讲清，不坚持苏格拉底提问。一次只补一个缺口，不把教材全部章节、内部路线依据或多段总结倒给用户。

## 出口与返回

出口标准写成可观察动作，例如「从空白文件写出两关节模型，修改关节轴并预测现象」，不写「读完教程」「看过文档」。

达到出口，或用户明确选择返回后：

1. 更新先修记录和 `tutor/user-prefs.md` 的能力状态。
2. 把 `tutor/STATE.md` 当前模式改回项目实现，写清返回 Bite。
3. 项目会话只读取返回摘要，再按 Phase 3 从原位置继续。
4. 未达到出口但用户仍要返回时，标「用户选择跳过」，不写成已通过。
