# Phase 4 · 收敛，然后复盘

全部里程碑通过后才进入。收敛没过，不开始复盘。

## 收敛

以 `spec/features.md` 为主线逐项核对：复刻项是否都已交付，豁免理由是否还成立。再看 `spec/deviations.md` 里还没收敛的行为差异。每一条给用户两个选择：对齐回去，或保留并写明理由。

清单和偏差簿都没登记、原项目却有的功能，是流程失败。补登记，向用户说明，请用户裁决该项是复刻还是豁免。

审计开启时，看 `tutor/STATE.md` 的知识依赖后置项：还有「待回访」的，在这之前展开并标为已闭环；来不及的，向用户说明并记为遗留。

## 复盘

收敛通过之后：

- 逐条看原作者那些核心决定的失效边界：约束变到什么程度就该推翻它
- 写 3 到 5 条能迁到用户本职工作的设计原则，每条配一个具体场景
- 出一道检验题：换一个新场景，让用户用刚写下的原则做决定，由 agent 点评

归档到 `tutor/phases/phase-4.md`。更新 `tutor/STATE.md`。列出仍未从代码确认的推断。停下。
