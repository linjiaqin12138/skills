# concept-writer

把一个概念写成一页，供以后链接。对话里当下的「听不懂」用 explain-it；要落盘的页用本 skill。

## 写什么、写到哪

概念页的正文要让读者**不靠外链**就能读懂「这一次」用到的东西：

1. **本次要用到的概念知识**：调用场景或代码里实际碰到的机制、名词、寄存器、约定。
2. **这些知识的依赖**：读懂上面那些点所必需的前置；缺了就在本页补到能接上，或链到已有概念页。
3. **讲到够用就停**：以「代码 / 场景里用到的点，都能在本页（或它所链的概念页）找到对应解释」为验收线。不写成百科，不把「去学」里的材料当成正文。

「去学」只服务想继续深入的读者：外链教程、手册、视频。删掉「去学」，读者仍应能完成页内承诺的理解任务。

## 先选模式

看调用里的「模式」，读完本页后只打开对应文件。

| 调用里写的 | 打开 |
|---|---|
| 简单，或没写模式 | `simple.md` |
| 中等 | `medium.md` |
| max | `max.md` |

没写模式就做简单模式。概念看起来适合做图，也不自行升到中等或 max。

## 调用方要给的

缺了先问，再动笔。

- 模式：简单 / 中等 / max
- 核心问题：这一页只回答一个
- 目标读者已经知道什么
- **本次用点**：代码路径或场景里会碰到哪些概念点（可带文件:行号）。教程调度时必给
- **依赖边界**：读者还缺哪些前置；哪些已有概念页可链
- 已核实的事实、公式、代码或素材。缺关键事实先问，不用通用知识编项目事实
- 输出路径。没给时：简单模式写 `docs/concepts/<slug>.md`；中等和 max 写 `docs/concepts/<slug>/<slug>.draft.md`，渲染到同目录 `<slug>.html`，素材进 `assets/`
- 概念与项目的关系（可选）。给了就写「回到项目」或等价对照，把用点映射到页内章节
- 偏好文件路径（可选）。给了就先读

## 三种模式都遵守

- 一页一个核心问题
- 正文覆盖本次用点及其依赖，讲到够用；「去学」不替代正文
- 事实核实过再写。推断标【合理推断】
- 不编造链接、公式、命令输出
- 不改项目实现代码，不写里程碑教程正文
- 已有另一种格式的概念页时不覆盖，先问调用方
