# explain-it：诊断式解释技能

目标：不是把内容再讲一遍，而是找到用户卡在哪里，选对**媒介 + skill**打通。

**禁止**在没选型的情况下直接手搓 HTML/Manim/GIF 并反复改布局——那正是「没有章法、改来改去」的来源。选型后读对应 `SKILL.md`，按其流程执行。

## 第一步：诊断卡壳类型

| 类型 | 特征信号 | 本质 |
|------|----------|------|
| A. 缺感知经验 | "没见过/想象不出来" "太抽象" | 纯语言无法落地到感官 |
| B. 缺背景知识 | "从某句话开始听不懂" 术语连环 | 前提链条断了 |
| C. 缺心智模型 | "每句话都懂，连起来不懂" | 碎片有，结构没有 |

快速问诊："从哪句话/哪个词开始听不懂？"
- "一开始就不懂" → B
- "字面懂，不知道在说什么" → C
- "脑子里没有画面" → A

## 第二步：选媒介（文字？图？动画？视频？）

先问一句（已能从问题里看出来就别问）：**「你更需要一段话、一张图、能点的演示，还是会动的动画/视频？」**

再按**信息形状**定默认媒介（用户指定优先）：

| 信息形状 | 默认媒介 | 不要选 |
|----------|----------|--------|
| 定义、动机、前提链、一句话锚点 | **文字** | 动图 |
| 结构/关系/对比（不依赖时间） | **静图** | 视频 |
| ≥3 概念怎么连、流程带分支、权衡表 | **交互 HTML 页** | 纯文字堆 |
| 状态逐步变（内存条、页表、协议握手） | **分步演示** | 无控件的循环片 |
| 请求在拓扑里走、架构「活起来」 | **架构流动画** | 分步状态机 |
| 增量只能来自「时间」或「第三维」（变换、轨迹、场） | **循环教学动画** | 静态 SVG 硬演过程 |
| 要旁白讲课、长叙事 | **讲解视频** | 嵌页面的 loop 动图 |

判据（借自 manim-teaching-figures）：**不占时间也不占第三维 → 别做视频/动画，静图或文字更好。**

卡壳类型 × 媒介的常用组合：
- A → 分步演示 / 循环动画 / 交互页（先给画面）
- B → 文字补台阶；缺画面时再叠静图或交互页
- C → 静图 / 交互页 / 对比表；过程类用分步演示

### 0. 现成素材优先于自制

通用概念先 WebSearch（B 站、YouTube、文档、带动画的科普）。搜到 → 链接 + 一句说明覆盖哪个断点，必要时用文字把素材接到当前代码。搜不到 / 项目专属逻辑 → 才走下面的 skill。

教程类项目：自制产物落盘到文档目录（如 `docs/concepts/assets/<slug>/` 或 `book/concepts/figures/<slug>/`），并在对应 md 里引用。

## 第三步：按媒介路由到 skill

路径约定（相对本仓库根）：
- 自有：`skills/<name>/SKILL.md`
- 第三方：`vendor/<name>/SKILL.md`（没有就按「第四步」准备）

| 媒介 | 调用 | 说明 |
|------|------|------|
| 文字 | 本 skill 内写完 | 类比、一句话版本、前提链、动机、误区；不另开 skill |
| 静图 | `skills/draw-diagram` | 路由 mermaid / fireworks / d2；见其 SKILL |
| 交互 HTML 页 | `vendor/answer-me-with-html` | 多面板讲解页；只写 Markdown draft，用 `bin/am-render` |
| 分步演示 | `vendor/courseware-builder` | 逐步高亮 + Simulate；内存/页表/握手类首选 |
| 架构流动画 | `vendor/dashmotion` | 自包含 HTML/SVG，连接线流动、请求点 hop |
| 循环教学动画 | `vendor/manim-teaching-figures` | 无声 loop mp4 嵌页面；有「该不该动 / 接缝」房规 |
| 讲解视频 | `vendor/manim-video` | 有旁白的长片；用户明确要「讲课视频」才用 |
| 落盘概念页 | `skills/concept-writer` | 「当下听懂」用 explain-it；要可链接的页再转这个 |

细节与上游地址见 [references/media-catalog.md](references/media-catalog.md)。

**一次只用一个主 skill**（可另加几句文字衔接）。不要并行开两个动画 skill。

## 第四步：vendor 里没有就当场 prepare

对上表每个 `vendor/<name>`：

1. 若已存在 `vendor/<name>/SKILL.md` → 直接 Read 并遵循。
2. 若不存在 → 按 `references/media-catalog.md` 里该条目的 prepare 命令，把上游 skill **稀疏检出或下载到** `vendor/<name>/`，写一份 `vendor/<name>/VENDOR.md`（上游 URL、许可、收录方式、日期）。
3. 需要被 Claude Code / Cursor 自动挂载时，再把该目录链到或复制进 `.claude/skills/<name>/`（本仓库惯例）；至少保证本回合能 `Read vendor/<name>/SKILL.md`。
4. prepare 失败（私有仓、网络、许可不明）→ 降级到下一档媒介（例如 manim → 分步 HTML → 静图 → 文字），并告诉用户缺了什么。

**不要**全局 `npm i -g` / 往用户家目录塞 skill 作为默认手段；仓库内 `vendor/` 是唯一来源。运行时依赖（Manim、ffmpeg）按该 skill 自己的说明装；缺系统包要 sudo 时停下让用户执行。

## 第五步：输出与验证

1. 先说诊断 + 选型（一句）：「卡在 A；用分步演示（courseware-builder）。」
2. prepare（如需）→ Read 目标 SKILL → 按它的流程产出。
3. 正文里给路径/链接；教程项目写进文档引用。
4. 结尾留验证钩子：复述 / 探测题 / 小判断。
5. 若是 B：列出「需要先补的知识点」，可提议逐个讲。

## 红线

- 不跳过选型直接「做个动画看看」
- 不在断点上同义反复
- 类比是桥，过桥要给正确定义
- 一次只补一个缺口；补完验证再补下一个
- 自制动画必须走已选 skill 的流程（含其「该不该动」、步骤数据、接缝检查等），禁止无契约手搓后反复改皮
