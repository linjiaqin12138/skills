# explain-it：诊断式解释技能

目标：不是把内容再讲一遍，而是找到用户卡在哪里，用对症的手段打通。

## 第一步：诊断卡壳类型

用户说"不懂"时，先判断（或直接问）属于哪种断点。三种根因：

| 类型 | 特征信号 | 本质 |
|------|----------|------|
| A. 缺感知经验 | "没见过/想象不出来" "太抽象" | 纯语言/符号无法落地到任何感官经验 |
| B. 缺背景知识 | "从某句话开始听不懂" 术语连环出现 | 前提链条断了，断点之前的东西不会 |
| C. 缺心智模型 | "每句话都懂，连起来不懂" | 信息碎片有，但组织不成结构 |

**快速问诊**：直接问"你觉得从哪句话/哪个词开始听不懂的？"——答案几乎直接指向根因：
- 答"一开始就不懂" → 缺背景（B）
- 答"能看懂字面意思，但不知道在说什么" → 缺心智模型（C）
- 答"脑子里没有画面" → 缺感知经验（A）
若用户答不上来，抛一个具体子问题探测："X 是指 Y 吗？"根据其反应定位。

## 第二步：对症选手段

### A. 缺感知经验 → 补感官通道
- 示意图 / 信息图（复杂结构用 `show_widget` 渲染交互式图示，见 kimi-widget 技能）
- 交互式动画（首选）：用 `show_widget` 做可播放/可拖拽/可逐帧推进的动画，用户可反复操控
  （需先读 kimi-widget 技能的 SKILL.md；移动端体验一般，复杂动画改用下方方案）
- GIF 动图：用 ipython 生成 matplotlib 动画导出 GIF，可下载
- 分帧示意图：过程拆成 3-5 张静态图配顺序解说，低配视频
- 录屏式步骤图：关键帧 + 标注箭头 + 解说文字
- 类比到日常经验（"电流像水流"）——最低成本首选
- 可操作的模拟器 / 小游戏 / 拖拽演示
- 顺序原则：先给一个粗糙的整体画面，再逐个零件加细节

### B. 缺背景知识 → 补台阶，别硬讲
- 回溯前提链：列出理解该概念所需的前置知识点清单，从断点处往回补
- 明确标注"先不用管 X"来降维，避免知识雪崩
- 给一句"一句话版本"（最简表述）作为锚点，再逐层加复杂度
- 讲动机：这个东西是为了解决什么问题而存在的，动机通了定义自然顺

### C. 缺心智模型 → 给结构
- 对比表：与易混淆概念并排，差异即边界
- 正例 + 反例："这是 X，这不是 X"
- 流程图 / 因果图 / 时间线 / 思维导图
- 口诀、框架、分类法（把碎片挂到骨架上）
- 常见误区先行："人们通常以为……其实……"

## 第三步：通用增强手段（不限类型，按需叠加）

- 讲故事：给抽象概念一个主角和情节
- 苏格拉底追问：不直接给答案，用问题引导对方自己推出结论
- 费曼验证：请对方用自己的话复述一遍，讲不清处就是没懂处，回到第一步重新诊断

## 输出规范

1. 诊断结论先说出来（一句话："你卡住的可能是 B 类——缺前置概念"），让用户确认
2. 每种根因给 1-2 个手段即可，不要一次堆全部
3. 用到视觉时优先 `show_widget`（需先读 kimi-widget 技能的 SKILL.md）
4. 结尾留一个验证钩子：让对方复述 / 问一个探测性问题 / 给一道小判断题
5. 若确实缺前置知识，明确列出"需要先补齐的知识点"清单，并可主动提出逐个讲

## 红线

- 不承诺生成真实视频（无此能力）；视觉手段的可行选项是 widget 交互动画、GIF、分帧图
- 不要在断点上重复原表述（"我的意思是……"同义反复无效）
- 不要用类比代替定义——类比是桥，过了桥要给正确定义
- 一次只补一个缺口，补完验证，再补下一个
