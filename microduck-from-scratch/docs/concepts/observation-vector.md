# 观测向量

## 一句话

观测向量是一条定长的小数数组。策略只读这一个数组，不读结构体字段名。

## 为什么需要

训练时，网络的第 n 个输入永远是同一种物理量。部署时如果第 n 格装了别的东西，网络不会报错，它会按训练时的含义去理解这个数，然后给出一个看起来正常、实际上会让机器人摔倒的动作。

TypeScript 里最接近的东西是一个没有 key 的 `number[]`，下标就是协议。对象字段名写错会在类型检查里爆；数组下标写错，运行时仍然是一个合法的 `number[]`。

## 最小示例

`examples/obs_layout.mjs` 用 15 个数模拟关节角。嘴在下标 9，策略不要它。跳过嘴之后，左髋多出来的 0.25 落在位置块第一格，嘴张开的 1.0 不出现。不跳过的话，1.0 会占住下一格，后面的关节全体串一位。

```bash
node examples/obs_layout.mjs
```

实测输出：

```text
跳过嘴，前 8 维: 0,0,0,0,0,-1,0.25,0
位置块是否含 1.0（嘴）: false
不跳过嘴，下标 9 起: 1,0,0
跳过嘴，下标 9 起: 0,0,0
```

前 6 个数是占位的陀螺仪和重力（直立时重力第三维是 -1）。第 7 个数 0.25 才是「关节角减去 home」。

## 素材

这条布局没有通用科普视频。它是 microduck 策略的输入契约，对照在 `reference/duck-control/src/obs.rs` 文件头的那张表。

## 回到项目

拼装发生在 `src/obs.rs` 的 `Observation::build`。嘴的跳过只写在 `joint_of`（`src/obs.rs:51`），读关节和 `scatter_action` 都走它。

## 自测

home 姿态下，位置块 14 个数应该全是 0。如果某一格是 home 的绝对角（比如 -0.4579），说明减 home 这步被漏了。
