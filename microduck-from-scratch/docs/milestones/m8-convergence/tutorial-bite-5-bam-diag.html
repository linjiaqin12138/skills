A

问题

C1 接口对齐已在 Bite 4 收口。C2 要解决仿真执行器与训练真值不对齐：训练用 BAM（电压 + 反电动势 + 摩擦），教程仿真仍是 XML 位置伺服。

已有症状（偏差 D34 / D35）：sit 与 roulade 调度正确，物理仍摔。M6 曾把 kp 加到 40 并放宽 forcerange，倒在同一时刻——不像 torque 上限。

一种剩余猜测仍在：是不是教程把 XML 的 kp 从 0.55 改成 8，反而把 sit 弄垮了？若不先否掉这条，下一 Bite 直接移植 BAM，失败时说不清是 BAM 没接好，还是增益对照做错了。

本 Bite 只做一件事：用可切换的基线增益跑 A/B 对照。A = 教程默认 kp=8 / kv=0.25；B = 官方 no-bam XML 原值 kp=0.55 / kv=0。不移植 BAM，不改 Rust。

不跑对照的代价：把「增益过大」与「缺 BAM」绑在一起，下一 Bite 无法单独证伪。

背景概念

【背景卡片】XML 位置伺服 PD vs BAM

  • 一句话：位置伺服用弹簧公式直接出力；BAM 先算电压，再经反电动势与摩擦才出力。两边的「kp」不是同一个物理量。
  • 为什么需要它：本 Bite 对照的是 XML 上两个 kp 数字。若把 BAM 的 kp_fw=200 当成「把 PD 的 kp 调到 200」，会误判对照结果。

【决策卡片】BAM 移植前要不要先做 kp=0.55 对照

  • 决策点：进入真正 BAM 移植之前，要不要先用 XML 增益 A/B 对照裁决归因。
  • 备选：
    1. 先对照再移植（所选，本 Bite）
    2. 直接移植 BAM（bam.mujoco.MujocoController）
    3. 把 kp 再加大，指望 sit 站住（同质于 M6 的 kp=40 实验）
  • 选择：备选 1。对照只动 env 钩子与诊断脚本，零架构风险；结果可证伪「教程增益过大」。
  • 放弃的成本：
    • 没选 2（直接移植）：立刻进入 C2 主线，少一轮实验日历。我们没要到这份速度——多花一整场 A/B 对照时间，换来可写进偏差簿的裁决证据。
    • 没选 3（再加大 kp）：动手成本最低，几行改增益就能再跑。我们没要到这份「再试一次同质实验」的机会——M6 已证 kp=40 同刻摔倒；再加大只会重复无效尝试，却占掉本 Bite 的对照窗口。
  • 失效边界：对照只能裁决「在 XML 位置伺服家族内，0.55 是否比 8 更像答案」。它不能证明 BAM 移植后一定物理通过；那要等下一 Bite 真正接入 BAM 再验。

H

细节展开

为什么 B 组 sit / roulade 也「失败」

B 组连站都站不住（z≈−0.11）。后续 sit / roulade 的 accepted=False、win_frames=0 是站立失败的连带现象，不是「no-bam 增益下技能反而更稳」。裁决时只取「B 站不住」这一条。

env 钩子与 XML 的关系

XML 里仍写着 kp=8 / kv=0.25。运行时 _apply_gains 用 env 基线覆盖执行器参数。对照不必改资产文件，也避免两组实验互相污染 XML。

原版训练的模型，跟官方对齐后怎么还会站不稳？

策略权重是原版的；仿真里的「舵机」还不是训练时那具舵机。 策略学的是「在 BAM 身体上，这组观测该出什么关节目标」；我们跑的是「在 XML 位置伺服身体上执行同一组目标」。两具身体对同一目标角的力矩响应不同，控制一拍接一拍地纠偏，就会漂、抖、乃至技能动作翻倒。

已对齐的是什么：MJCF 几何/惯量/阻尼、61 维观测契约、ONNX 权重、调度与 RPC。没对齐的是执行器层——训练用 BAM（电压 → 反电动势 → 摩擦 → 力矩，kp_fw≈200），教程仿真仍是 MuJoCo <position> PD（力矩 = kp×误差 − kv×角速度）。Bite 5 的「官方 no-bam kp=0.55」也不是训练分布，而是官方自己的降级展示路径；策略从未在那条路径上学会站稳，所以 B 组站不住是预期，不是反例。

为什么走路/站立有时还能过、sit/roulade 不行：短杠杆、近站立姿态对执行器模型较不敏感；深蹲与前滚翻是长杠杆、大力矩，误差被放大。M6 把 PD 的 kp 加到 40 仍同刻摔倒，说明不是「弹簧不够硬」，而是「弹簧公式本身就不是训练时那条链」。

  • 放弃了什么：在缺 BAM 时假装「权重官方 + 几何官方 = 行为官方」——省掉执行器移植，却把 sim-to-sim 误差赌在策略鲁棒性上。
  • 赌了什么：域随机化与 feedforward 策略能吞掉一部分执行器失配（走几步验收能绿）；失效边界是大力矩技能与「零命令静站几乎不动」这类高要求场景（见 Q38 漂移）。
  • 失效边界：移植 BAM 之后若仍摔，就不能再把锅甩给「缺 BAM」——那时才查碰撞资产、timestep、观测噪声、或权重本身。

对齐了仿真身体，是不是就能 sit / roulade？

不能打包票。BAM 是必要项、也是当前最强嫌疑，但「接上 BAM = 技能物理通过」不是定理。

官方把两具身体分开用（microduck_rl README）：

  • robot_walk.xml：走路任务——故意砍掉躯干/头碰撞（摔倒成本低）
  • robot_groundcontact.xml：SitStand / Roulade / GroundPick 等——精选 11 个会碰地的 collision geom，身体能真躺在地上

我们现在整场仿真都挂 robot_walk.xml。只换 BAM、不换碰撞，深蹲贴地与前滚翻「头过地」仍可能物理不对。

次要缺口还有两处：timestep（教程 1ms，训练侧常见 5ms）；观测噪声（训练 gyro 有噪，我们喂干净值）。BAM 之后若仍摔，排查顺序：碰撞资产 → timestep → 观测噪声 → 权重本身。

Bite 6 的诚实验收口径：先接 BAM，用 sit/roulade 物理断言试一次；不过就按上表补 groundcontact（必要时 timestep），而不是宣布「BAM 假说错了」。对照实验（Bite 5）只能否掉「kp 过大」；不能证明 BAM 移植后一定过——那要实测。
