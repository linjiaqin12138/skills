3) yaw 门是同义反复。odometry 的 yaw 直接由同一 IMU 四元数读出，测试又是拿
   「同一 IMU 真值」做比较，所以 max_yaw_error 恒为 0 只证明四元数→yaw 的管线
   没写错，不构成任何精度证据。同理 anchor_switches 里的锚点选择质量没有被独立
   真值校验过。

4) 纵向（z）没有门槛。live 测试只卡水平误差；真值/估计的 z 都打印了但没有断言。
   上游 anchors.rs 的注释明确主张 ALPHA16「stands at the true height（V15 高了
   3.7mm）」，这个主张在本次端到端验收里没有被验证。

5) 运动形态覆盖窄。只跑 vx=0.8 直行与 vyaw=2.0 纯转身。测试源码里其实留了
   TurnRate(1.5)、Combined(0.8)、Combined(1.5) 的 probe 分支（ODOMETRY_LIVE_PROBE），
   但默认用例集不跑它们：斜向/后退/边走边转/慢速/急停都没有端到端覆盖。

6) 「robot.state 不含 odom」的端到端没验。live 测试根本不起 daemon（不走 RPC），
   m08-b01.sh 收的 robot.state 推送帧也没断言没有 odom 键；这一条目前只有
   main.rs 的单元测试 internal_odometry_never_enters_robot_state_rpc 兜着。

7) 只比终点，不比路径。估计轨迹与真值轨迹只在终点对水平误差，路径形状/中间点
   不比；max_tick_jump<0.02 只约束单拍位移，排不掉「整体偏一点但每拍都很平滑」
   的系统偏差（本次前行的 0.10m 残差就正是这一类）。

8) 跌倒/滑行期间的里程计行为只有单测覆盖（滑行不推进估计或 pending、
   disable/scheduler reset 不清零、跌倒恢复不重建），没有 live 场景跑一遍。

9) 仓库里没有生成 impl/tests/fixtures/odometry_reference_400.csv 的脚本，fixture
   的上游出处无法由仓库自证。见下面附录：我这次在仓库外独立重算了上游轨迹。

===== 附录（verifier 自查，不属于 accept 脚本）：上游逐位一致性的独立复算 =====

背景：脚本 A 项写「400 拍参考轨迹与上游逐位一致」，但 impl 侧的单测
every_reference_tick_matches_upstream_bitwise 实际是「impl 的输出 == 一份签入的
CSV」，CSV 是不是上游产出的，仓库本身证明不了。

我做的事（全部在仓库外，不改仓库）：
  1. cp upstream 的 kinematics / duck-ipc-proto / odometry 三个 crate 到
     /tmp/upstream-mini，写一份只含这三个成员的最小 workspace（去掉
     duck-ipc-proto 的 dev-dependencies，否则离线解析会拉 tempfile），用
     docker cp 送进容器。
  2. 容器内 CARGO_TARGET_DIR=/tmp/upstream-target cargo build -p odometry --offline
     ——用的是上游自己的 Odometry::alpha()（即 Model::alpha() 从
     kinematics/assets/alpha/robot_walk.xml 解析出的 MJCF 树 + upstream/odometry
     的 ALPHA16 锚点）。
  3. 加一个 bin 重放上游 dump_reference_trajectory 同款合成轨迹
     （joints[1]=0.15sin(0.05t)、[2]=0.30sin(0.07t)、[3]=0.20cos(0.07t)、
     [12]=0.30cos(0.07t)、[13]=0.20sin(0.07t)，quat=roll_quat(0.10sin(0.05t))），
     按 fixture 同格式（tick,x,y,z,yaw,foot,anchor_x,anchor_y，{:.17e}）打印。

结果：
  - 上游重算结果与 impl/tests/fixtures/odometry_reference_400.csv 逐行比较：
    400 行 × (x, y, z, yaw, anchor_x, anchor_y) 的 f64 to_bits 全部相同，
    anchor_foot 也全部相同；不一致处数 0，最大绝对差 0。
  - 另核对 impl/src/odometry.rs 的 ALPHA16 与 upstream/odometry/src/anchors.rs 的
    ALPHA16：每脚 16 点，坐标逐位相同。
  - 也就是说：签入 fixture 确由上游代码产生，而 impl 单测又证明 impl 输出逐位
    等于该 fixture（本轮 cargo test 已过），故 impl ≡ upstream 在这 400 拍上成立。
    A 项的「上游逐位一致」这次有了仓库外的独立佐证。
  （第一次比对出现差异是我自己的笔误：right_knee 我写成了 0.05t，上游与 impl
   都是 0.07t。改正后完全一致。这说明差异可定位，不是「差不多就算过」。）

复现方式（容器内）：
  cd /tmp/upstream-mini && CARGO_TARGET_DIR=/tmp/upstream-target \
      cargo build -p odometry --offline --bin gen_ref && /tmp/upstream-target/debug/gen_ref
