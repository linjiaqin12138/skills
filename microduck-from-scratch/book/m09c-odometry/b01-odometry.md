机器人不知道自己走了多远。策略是开环的：给一条向前走 10 秒的命令，它可能走成弧线，也可能偏出 30cm。这一课给出一个纯软件的相对里程计，让机器人自己估出「相对起点走了多远、转了多少度」。

## 问题

仿真里能查 MuJoCo 的 `body_pos`，真机上没有任何测量。走完一段路之后，除了看它有没有摔倒，没有人能说它偏了多少。

M9c 先清 CPU 侧的调度与安全债。Bite 1 交付跌倒预测与软倒恢复。Bite 2 交付相对里程计。

上游把这套算法放在独立的 `odometry` crate。它的腿链几何来自 `kinematics` crate 解析 MJCF 得到的模型。那是 D55，属于 M10。

只为跑一个估计器就把通用运动学整套拉进来，代价太大。本课只需要两个脚 site 的位姿。

线上的 `robot.state` 仍不含 odom 字段。那是 D50，也挂 M10。本课的估计只走内部诊断。

## 设计

![M9c 当前架构：miniduckd 内新增 impl/src/odometry.rs，无新进程、RPC、网络边与依赖](arch.svg)

每拍做同一件事：

```flow TB
[新样本] -> [两脚 site 位姿]
两脚 site 位姿 -> [由当前锚点投影躯干]
由当前锚点投影躯干 -> [扫描 32 个鞋底点]
扫描 32 个鞋底点 -> {有候选低于 10mm}
{有候选低于 10mm} -> [清空 pending] : 没有
{有候选低于 10mm} -> [同脚加一拍] : 同脚
{有候选低于 10mm} -> [换脚重开候选] : 换脚
同脚加一拍 -> {连续两拍}
换脚重开候选 -> {连续两拍}
{连续两拍} -> [换锚并重投影] : 是
{连续两拍} -> [输出 position 与 yaw] : 否
换锚并重投影 -> [输出 position 与 yaw]
```

六个要点：

- **局部两足 FK**：只实现估计要用的两条腿链，不引入通用 kinematics crate。
- **ALPHA16 鞋底网格**：每脚 16 个点，共 32 点投到世界系。
- **竞标门限**：世界 z 低于 10mm 的最低点才有资格。
- **两拍确认**：同一脚连续两拍才换锚。
- **冻结首次候选**：pending 记住候选首次出现时的局部点与世界 XY。
- **没有 reset 方法**：原点由首次更新的左脚 site 定死。

估计跨相位存活：滑行拍、盲拍、disable、scheduler reset、跌倒恢复都不清零它。

yaw 直接从归一化的 IMU 四元数读出，不积分陀螺。

估计进 `FrameSnapshot` 供集成测试读，RPC 载荷不变。

聚焦模块见 [odometry 子图](../arch/odometry.svg)。也可查看[本课架构差分](figures/arch-diff.svg)。

## 架构决定

**局部两足 FK，不拉通用 kinematics crate。** 另一个做法是直接依赖上游 `odometry` 或 `kinematics`。那样能复用上游已交叉验证的 FK，代价是本课要处理 MJCF 解析与站点映射，还要提前兑现 D55。局部实现只覆盖估计器需要的两个 foot site，代价是将来 D55 落地时要替换它，而不是长期维护两套几何。

**没有 reset 方法，原点由首帧定死。** 首帧用左脚 site 的位置建立相对原点，之后任何事件都不改它。跌倒恢复后重新选原点，会让「机器人从哪出发」这件事在一次摔倒后失去意义。

**估计放在内部诊断，线上字段留给 M10。** 集成测试要读估计值，就把它放进 `FrameSnapshot`。`robot.state` 的载荷保持原样，D50 仍挂 M10。

| 方案 | 代价 | 结论 |
|---|---|---|
| 局部两足 FK + ALPHA16 | 要自证 FK 与上游等价 | 采用 |
| 依赖上游 kinematics 或 odometry | 提前兑现 D55 | 不采用 |
| 等 M10 完整 kinematics 再移植 | M9c 没有里程计 | 不采用 |

没有新增进程、RPC 方法、网络边或依赖。完整取舍见[决定 0007](../../decisions/0007-m9c-odometry.md)。

## 代码领读

### 鞋底最低点是接触代理

双足站姿里，唯一可靠地贴在地面上的东西是鞋底。所以估计器不去找「接触力」，而是找「世界 z 最低的那个鞋底点」。地面是平的，贴地的那一点高度近似为 0；它低于 10mm 就说明这一拍有脚落地了。

每脚 16 个点，来自上游生成的 ALPHA16 鞋底网格。32 个点全投到世界系，取最低的一个。

```rust src=impl/src/odometry.rs lines=372-395
```

注意 `lowest_z` 初值就是 10mm。没有任何点低于它，这一拍就没有候选。

### 一拍不能抢锚，pending 冻结首次候选

换锚要连续两拍同一个脚。理由是 FK 与 IMU 都带噪声：某一拍算出的最低点可能只是抖动。

pending 里存的不是当前值，而是这个候选**首次出现时**的局部点与世界 XY。确认时沿用这一份，于是换锚那一拍的躯干位置和上一拍连续。

```rust src=impl/src/odometry.rs lines=331-360
```

同一脚才累加计数。换成另一只脚，计数重新从 1 开始。没有任何候选时，pending 直接清空。

### 投影：躯干位置由锚点反推

锚点被钉在它成为锚点那一刻的世界 XY 上。躯干位置就是「锚点减去当前脚到锚点的偏移」。

```rust src=impl/src/odometry.rs lines=362-370
```

位置因此永远连续：锚点不动时，脚在动，位置跟着动。

### 一拍的数据要新

估计器只吃新鲜且 IMU 收敛的样本。滑行拍沿用旧样本，盲拍没有样本，两者都不推进估计。

```rust src=impl/src/control.rs lines=494-525
```

门控在控制循环里，不在估计器里。估计器自己不知道样本新不新。

### 估计不随跌倒或 disable 清零

估计器在循环外创建一次。相位切换、scheduler reset、跌倒恢复都不重建它。

```rust src=impl/src/control.rs lines=440-452
```

跌倒恢复完成后只清 scheduler 与策略记忆。估计器和锚点原封不动，所以机器人摔一跤之后仍知道自己站在哪。

### yaw 是读出来的，不是积出来的

yaw 直接取归一化 IMU 四元数。IMU 已经把陀螺融合进了这个四元数，再积一次会二次积分并累积漂移。

### 参考轨迹对拍

`impl/tests/fixtures/odometry_reference_400.csv` 存着 400 拍的逐位期望值。单测 `every_reference_tick_matches_upstream_bitwise` 把位置、yaw、锚点 XY 和换脚次数逐位对比，锚点在这 400 拍里换了 9 次脚。

## 坑

**1.5mm 的鞋底点抄写错误。** 手抄 ALPHA16 时有一处 z 抄错 1.5mm。自己的单测查不出来，因为它们都以这份表为基准。只有与上游逐位对拍才暴露。抄常数必须配一条跨实现的逐位比较。

**vyaw=0.8 转不动。** 早期转身场景用 vyaw=0.8，实际 yaw 只变了 0.07 rad，达不到 0.5 rad 的门槛。场景本身没有成立。改用 vyaw=2.0 后实测 |yaw| 约 3.04 rad。先确认实验跨过机制门槛，再动机制。

**六个样本只有四条不同轨迹。** verifier 复核发现 forward-2 与 forward-3 逐位相同，turn-1 与 turn-3 逐位相同。handmade sim 近乎确定性，三个新进程给的是重复，不是分布。中位数 0.063151 只由四个值决定，谈不上置信区间。

**yaw 误差为 0 是同义反复。** 估计的 yaw 就是同一份 IMU 四元数读出来的，测试又拿同一 IMU 真值比较，所以恒为 0。它只证明四元数到 yaw 的管线没写错，不是精度证据。

**误差门余量偏薄。** 门是 0.12m，本次最坏值占 86%。再收紧会不稳，放宽会掩盖真实漂移。

## 自测

**1. 某一拍出现一个更低的鞋底点，下一拍没有更低的点。锚点会怎样？**

- A. 立刻换到那个点
- B. 不换，pending 记下这个候选
- C. 估计清零
- D. 那个点成为新的世界原点

<details>
<summary>答案</summary>

B。换锚要同一脚连续两拍。第一拍只记候选，A 会让 FK 抖动直接搬走锚点。
</details>

**2. 确认换锚时沿用 pending 里冻结的世界 XY，有什么作用？**

- A. 让位置跳到新的足印
- B. 让换锚那一拍的位置保持连续
- C. 减少 FK 计算量
- D. 记录哪只脚在承重

<details>
<summary>答案</summary>

B。锚点被钉在它首次成为候选时的位置。若用确认那一刻的 XY，位置会在换锚瞬间跳一次。
</details>

**3. 控制循环读到滑行样本时，估计与 pending 会怎样？**

- A. 用旧样本继续更新
- B. 估计清零
- C. 两者都不动
- D. 重建估计器

<details>
<summary>答案</summary>

C。门控要求样本新鲜且 IMU 收敛。滑行拍不推进估计，也不推进 pending 计数。
</details>

**4. 机器人跌倒进入 Limp，之后回 Driving。里程计的原点会怎样？**

- A. 跌倒时清零
- B. 改用新的左脚位置
- C. 保持不变
- D. 随 scheduler reset 一起重建

<details>
<summary>答案</summary>

C。估计器在循环外创建一次，不随相位与调度器生命周期重建。跌倒恢复只清策略记忆。
</details>

**5. yaw 为什么直接读 IMU 四元数，不积分陀螺？**

- A. 陀螺在总线协议里没有字段
- B. 四元数已是 IMU 融合后的姿态，再积分会二次积分并漂移
- C. 四元数换算成角度更快
- D. 上游也这么写，没有别的选择

<details>
<summary>答案</summary>

B。上游的头向本来就是启动相对量，积分只会把漂移累加起来。D 是循环论证。
</details>
