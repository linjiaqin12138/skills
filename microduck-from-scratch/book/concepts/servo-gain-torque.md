# 舵机 gain 与 torque：弹簧硬度与总开关

## 一句话

位置舵机内部是一根弹簧：`gain`（位置环 P 增益）是弹簧的硬度，`torque` 是弹簧的总开关——关掉它，舵机不再输出任何力。

## 「gain=200 是哪来的？」

200 和 50 不是算出来的物理量，是原型 alpha 调好后写进舵机**增益寄存器**的两个数（`src/safety.rs:50-55`，注释标明是原型 alpha 默认值）。这个寄存器是舵机固件自己定义的一个标度——不是牛顿米、不是度数，没有 SI 单位，单看「200」说不出它有多硬。

所以教程里真正有物理意义的只有**相对关系**：200:50 = 4:1，站立弹簧是软倒弹簧的 4 倍硬。

它到物理世界的桥是仿真体的映射 `kp_sim = 8 × gain/200`（`sim/duck_body.py:85-100`）：gain=200 对应 kp=8，gain=50 对应 kp=2。下面网页演示里的「弹簧硬度」走的就是这条映射。

真机侧，这个数经 `write_position_p_gain` 写进 XL330 的 Position P Gain 寄存器，I/D 同时被钉在 0；代码注释说明这些是 RAM 寄存器、每次上电恢复出厂值（`reference/duck-control/src/bus.rs:541-561`）。寄存器的具体量程和出厂默认值以官方 e-Manual 为准（链接见「素材」一节）。

## 为什么需要

舵机（本项目用 Dynamixel XL330）工作在位置模式时，内部跑一个 P 控制环：输出力矩 ∝ （目标角度 − 当前角度）。比例系数就是 Position P Gain——增益寄存器里的一个数，固件自定义的标度（出处见上一节）。这不是「速度」也不是「功率」，是**弹簧硬度**：

- **gain 大（硬弹簧）**：误差一点点就输出大力矩。站着的鸭子要硬——重力、落脚冲击、被人推一下，都得顶回去。本项目满增益 200。
- **gain 小（软弹簧）**：同样的误差只输出小力矩。倒下的鸭子要软——身体压在地板上，硬弹簧会让电机顶着地板较劲，齿轮箱和机身较劲到自己坏。本项目软倒增益 50。
- **torque off（抽掉弹簧）**：舵机完全不输出力，goal 寄存器照写也没用。整机关节变成纯机械件，在重力下自由瘫软。

两个嵌入式读者习以为常、软件读者容易踩的事实：

1. **力矩是有代价的**。硬弹簧顶住偏差=电机持续输出力矩=发热、耗电、磨齿轮。「一直硬」不是免费的默认态。
2. **torque/gain 存在舵机的 RAM 里，跨进程存活**。daemon 崩溃重启，舵机还记着上次的 torque on——一台站着的机器人不会因为控制进程重启而自己倒下（除非新进程主动把它放倒）。这条事实是 M5「启动不动」设计（偏差 D9）的物理基础。

## 最小示例

**网页演示（推荐）**：浏览器直接打开 [assets/servo-gain-torque/index.html](assets/servo-gain-torque/index.html)（单文件、无依赖，双击即开）。三只机械臂同屏摆：硬弹簧扛在高位、软弹簧明显下垂、卸力自由垂落挂住。拖「弹簧硬度」滑块、开关 torque、按预设，随便折腾中间那只实验臂。页面上还有独立的 kv（刹车强度）滑块和一个「硬弹簧 + 无刹车」破坏实验按钮——点它能亲眼看到 Q48 里说的「没有 kv 就振荡」：腿冲过目标来回荡，停不下来。

**数字版对照**：同一个单关节仿真的 python 版，不碰项目代码——一根杆、目标水平、重力下拽，舵机力矩 = `kp×(目标−角度) − kd×角速度`。三种工况各跑一遍：

```bash
docker compose exec rust python3 docs/concepts/assets/servo-gain-torque/spring_demo.py
```

容器内实测输出：

```text
kp=8 （满增益 gain=200）
  0s:  -0deg 1s: -38deg 2s: -29deg 3s: -31deg 4s: -31deg 5s: -31deg 6s: -31deg 7s: -31deg 8s: -31deg
  → 稳态 -31deg
kp=2 （软倒增益 gain=50）
  0s:  -0deg 1s: -70deg 2s: -69deg 3s: -58deg 4s: -67deg 5s: -63deg 6s: -64deg 7s: -64deg 8s: -63deg
  → 稳态 -63deg
卸力（torque off，只剩摩擦）
  0s:  -0deg 1s:-102deg 2s:-127deg 3s: -56deg 4s: -98deg 5s:-102deg 6s: -76deg 7s: -96deg 8s: -92deg
  → 稳态 -92deg
```

读法：满增益扛在 −31°（P 环的静态下垂——弹簧硬≠纹丝不动）；软倒增益下垂到 −63°，杆还在被「托着」但已经不怎么较劲；卸力后杆子垂到 −90° 挂在那，荡几下被摩擦耗停。脚本里 `kp` 与鸭子 `gain` 的对应关系就是仿真体里的映射（见上）。网页和这个脚本是同一个模型（重力、步长、积分方式逐行一致），三个预设的稳态角度两边对得上；脚本里的 theta/omega 就是角度/角速度的代号，网页版不碰这两个词。

## 回到项目

- trait 上的两个方法：`set_gain` / `set_torque`（`src/io.rs:71-78`；`imu_ready` 也在这一段）
- 两个安全数字：`gain_running=200` / `gain_limp=50`（`src/safety.rs:50-55`，原型 alpha 默认值）
- 软倒阶段主动要 50：`Phase::Limp` 的 apply（`src/control.rs:402-405`）
- 增益缓存去重（值不变不重写总线）：`src/safety.rs:293-300`
- 仿真侧映射：`kp_sim = 8 × gain/200`，torque off 清零执行器三参数（`sim/duck_body.py:85-100`）；启动默认 torque on、gain=200，模拟舵机 RAM 跨进程存活（`sim/duck_body.py:74-77`）

## 自测

鸭子摔倒后，为什么控制循环选择「目标跟随实测位置 + gain 50」，而不是直接 `set_torque(false)` 一关了事？（提示：卸力的杆子会自由落体到 −90°；倒下的鸭子头壳和舵机要承受全部撞击，而且 M5 的设计里「起来之后恢复站立」需要从软倒态斜坡回 home——全瘫的机器人没有「斜坡」可言。）
