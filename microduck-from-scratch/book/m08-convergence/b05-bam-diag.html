B

背景概念

【背景卡片】XML 位置伺服 PD vs BAM

  • 全称：PD = Proportional–Derivative（比例-微分）控制。BAM = Better Actuator Models——Rhoban 开源执行器模型库，包名 bam。

一句话：位置伺服用弹簧公式直接出力；BAM 先算电压，再经反电动势与摩擦才出力。两边的「kpk_p」不是同一个物理量。

为什么需要它：本 Bite 对照的是 XML 上两个 kpk_p 数字。若把 BAM 的 kp,fw=200k_{p,\mathrm{fw}}=200 当成「把 PD 的 kpk_p 调到 200」，会误判对照结果。

公式版。θ\theta 是当前角，θ∗\theta^* 是目标角，ω\omega 是角速度，τ\tau 是力矩。

  • 位置伺服 PD：τ=kp(θ∗−θ)−kvω\tau = k_p(\theta^*-\theta)-k_v\omega。误差乘 kpk_p 直接变力矩，kvωk_v\omega 是阻尼。
  • BAM 玩具：V=clamp⁡(kp,fw(θ∗−θ),±Vmax⁡)V=\operatorname{clamp}(k_{p,\mathrm{fw}}(\theta^*-\theta),\pm V_{\max})，i=(V−Keω)/Ri=(V-K_e\omega)/R，τ=Kti−fsign⁡(ω)\tau=K_t i-f\operatorname{sign}(\omega)。

两条链的差别：PD 一步从误差到力矩。BAM 多走两步——误差先变电压，电压减反电动势 KeωK_e\omega 变电流，电流乘 KtK_t 才是力矩，再减摩擦。kp,fwk_{p,\mathrm{fw}} 乘出电压（伏特），PD 的 kpk_p 乘出力矩（牛·米）。单位不同，数字不可比。

排版如下。代码里 Vmax⁡V_{\max} 取 12 伏。逐符号念法写在本页「细节展开」。

位置伺服 PD · 误差到力矩，一步
τ=kp (θ∗−θ)−kv ω\tau = k_p\,(\theta^* - \theta) - k_v\,\omega
BAM · 误差到电压，再到电流，再到力矩
V=clamp⁡(kp,fw (θ∗−θ), ±Vmax⁡)V = \operatorname{clamp}\bigl(k_{p,\mathrm{fw}}\,(\theta^* - \theta),\ \pm V_{\max}\bigr)
i=V−Ke ωR,τ=Kt i−f sign⁡(ω)i = \frac{V - K_e\,\omega}{R}, \qquad \tau = K_t\,i - f\,\operatorname{sign}(\omega)

H

细节展开

为什么 B 组 sit / roulade 也「失败」

B 组连站都站不住（z≈−0.11）。后续 sit / roulade 的 accepted=False、win_frames=0 是站立失败的连带现象，不是「no-bam 增益下技能反而更稳」。裁决时只取「B 站不住」这一条。

env 钩子与 XML 的关系

XML 里仍写着 kp=8k_p=8 / kv=0.25k_v=0.25。运行时 _apply_gains 用 env 基线覆盖执行器参数。对照不必改资产文件，也避免两组实验互相污染 XML。

原版训练的模型，跟官方对齐后怎么还会站不稳？

策略权重是原版的；仿真里的「舵机」还不是训练时那具舵机。 策略学的是「在 BAM 身体上，这组观测该出什么关节目标」；我们跑的是「在 XML 位置伺服身体上执行同一组目标」。两具身体对同一目标角的力矩响应不同，控制一拍接一拍地纠偏，就会漂、抖、乃至技能动作翻倒。

已对齐的是什么：MJCF 几何/惯量/阻尼、61 维观测契约、ONNX 权重、调度与 RPC。没对齐的是执行器层——训练用 BAM（电压 → 反电动势 → 摩擦 → 力矩，kp,fw≈200k_{p,\mathrm{fw}}\approx 200），教程仿真仍是 MuJoCo <position> PD（τ=kp(θ∗−θ)−kvω\tau=k_p(\theta^*-\theta)-k_v\omega）。Bite 5 的「官方 no-bam kp=0.55k_p=0.55」也不是训练分布，而是官方自己的降级展示路径；策略从未在那条路径上学会站稳，所以 B 组站不住是预期，不是反例。

为什么走路/站立有时还能过、sit/roulade 不行：短杠杆、近站立姿态对执行器模型较不敏感；深蹲与前滚翻是长杠杆、大力矩，误差被放大。M6 把 PD 的 kpk_p 加到 40 仍同刻摔倒，说明不是「弹簧不够硬」，而是「弹簧公式本身就不是训练时那条链」。

  • 放弃了什么：在缺 BAM 时假装「权重官方 + 几何官方 = 行为官方」——省掉执行器移植，却把 sim-to-sim 误差赌在策略鲁棒性上。
  • 赌了什么：域随机化与 feedforward 策略能吞掉一部分执行器失配（走几步验收能绿）；失效边界是大力矩技能与「零命令静站几乎不动」这类高要求场景（见 Q38 漂移）。
  • 失效边界：移植 BAM 之后若仍摔，就不能再把锅甩给「缺 BAM」——那时才查碰撞资产、timestep、观测噪声、或权重本身。

术语：域随机化与 feedforward 策略

  • 域随机化（domain randomization）：训练时每一场随机打乱仿真参数——质量、摩擦、电机常数各采一个值。策略见过许多「不一样的身体」，部署环境偏一点不崩。它能吞小失配，吞不掉「换了一条动力学链」这种大失配。
  • feedforward 策略：策略网络输出的不是力矩，而是目标关节角（前馈目标）。底层由舵机位置环去执行这个角度。好处是策略不绑定具体执行器；代价是底层响应一换，同一组目标角走出的轨迹就不同。

对齐了仿真身体，是不是就能 sit / roulade？

不能打包票。BAM 是必要项、也是当前最强嫌疑，但「接上 BAM = 技能物理通过」不是定理。

官方把两具身体分开用（microduck_rl README）：

  • robot_walk.xml：走路任务——故意砍掉躯干/头碰撞（摔倒成本低）
  • robot_groundcontact.xml：SitStand / Roulade / GroundPick 等——精选 11 个会碰地的 collision geom，身体能真躺在地上

我们现在整场仿真都挂 robot_walk.xml。只换 BAM、不换碰撞，深蹲贴地与前滚翻「头过地」仍可能物理不对。

次要缺口还有两处：timestep（教程 1ms，训练侧常见 5ms）；观测噪声（训练 gyro 有噪，我们喂干净值）。BAM 之后若仍摔，排查顺序：碰撞资产 → timestep → 观测噪声 → 权重本身。

Bite 6 的诚实验收口径：先接 BAM，用 sit/roulade 物理断言试一次；不过就按上表补 groundcontact（必要时 timestep），而不是宣布「BAM 假说错了」。对照实验（Bite 5）只能否掉「kp 过大」；不能证明 BAM 移植后一定过——那要实测。

位置伺服力矩、积分、半隐式欧拉，式子在说什么

位置伺服算的是这一下的劲。积分把这股劲加成角度。半隐式欧拉是代码里走一小步的办法。

公式排版也在「背景概念」。这里把每条式子念成一句。

位置伺服 PD · 误差到力矩，一步
τ=kp (θ∗−θ)−kv ω\tau = k_p\,(\theta^* - \theta) - k_v\,\omega

念出来：τ=kp(θ∗−θ)−kvω\tau=k_p(\theta^*-\theta)-k_v\omega。也就是硬度 ×（目标角 − 当前角）− 阻尼 × 角速度。

符号念法
τ\tau力矩，这一下的劲
θ\theta当前角度
θ∗\theta^*目标角度
ω\omega角速度，转得多快
kpk_p弹簧硬度
kvk_v阻尼，刹车有多重

括号是目标角减去当前角，也就是还差多少。差得越大，往回拉得越狠。

kpk_p 把角度差换成力矩。同样差 0.1 弧度，kpk_p 越大，出力越大。

减号后面是阻尼。已经朝目标转，这份阻尼把劲减小。正在背离目标转，这份阻尼把劲加大。kvk_v 决定刹车有多重。

积分负责的是：这股劲一直推下去，角度最后停在哪。

连续式 · 力矩积成角速度，角速度积成角度
Iθ¨=τ(θ,ω)I\ddot\theta = \tau(\theta,\omega)
ω(T)=ω0+∫0Tτ(t)I dt\omega(T) = \omega_0 + \int_0^{T} \frac{\tau(t)}{I}\,dt
θ(T)=θ0+∫0Tω(t) dt\theta(T) = \theta_0 + \int_0^{T} \omega(t)\,dt

Iθ¨=τI\ddot\theta=\tau。惯量是有多沉。同样的劲，越沉，角加速度越小。角加速度就是力矩除以惯量。

末角速度 = 起步角速度 + 把角加速度沿时间加起来。积分号就是沿着时间一路加，从 0 加到 TT。玩具里 TT 是 5 秒，起步角速度是 0。

末角度 = 起步角度 + 把角速度沿时间加起来。速度是劲的累积。角度是速度的累积。起步角度是 0.5，目标角度是 0。

代码用小步相加，代替积分号。5 秒切成 2500 步，每步 0.002 秒。

代码的一步 · 先更新角速度，再用新角速度更新角度

先改速度，再用刚改完的速度改角度。显式是用旧数算新数。隐式是式子里已经带着新数。这里只在角度那一步用了新速度，所以叫半隐式。

τn\tau_n 在更新之前就算好。它就是位置伺服按旧角度、旧角速度算出的力矩。玩具惯量 II 是 0.01。

每一步先做位置伺服，得到 τn\tau_n。再做半隐式欧拉，得到新的角速度和新的角度。2500 步加完，就等于那两条积分积满 5 秒。

BAM 的三条公式在说什么

BAM 先算电压，再算电流，最后才得到力矩。 力矩算出来之后，后面仍是上一节那两步。力矩加成角速度，角速度再加成角度。

kp,fwk_{p,\mathrm{fw}} 按实验取 8 或 200。电源是 ±12 伏。Kt=0.08K_t=0.08，Ke=0.05K_e=0.05，R=1.5 ΩR=1.5\,\Omega。摩擦 f=0.015 N⋅mf=0.015\,\mathrm{N\cdot m}。

kp,fwk_{p,\mathrm{fw}} 把角度差换成电压，单位是伏每弧度。差 1 弧度，没封顶时电压就是 kp,fwk_{p,\mathrm{fw}} 伏。

电源只有 ±12 伏。角度差再大，电压到 12 伏就停住。kp,fw=200k_{p,\mathrm{fw}}=200 时，差到约 0.06 弧度就已经顶满。0.06 弧度约 3.4°。

kp,fw=8k_{p,\mathrm{fw}}=8 时，要差到 1.5 弧度才顶满。起步的 0.5 弧度还在线性段，对应电压是 4 伏。

念出来：i=(V−Keω)/Ri=(V-K_e\omega)/R。反电动势是 KeωK_e\omega。

电机转得越快，自己顶回来的电压越大。留下来推电流的，是指令电压减去这份反电动势。停着的时候角速度是 0，反电动势是 0，电流就是 V/RV/R。

念出来：τ=Kti−fsign⁡(ω)\tau=K_t i-f\operatorname{sign}(\omega)。电流换成的劲，再减去一份和转动方向对着干的摩擦。

KtiK_t i 是电磁力矩。电流越大劲越大，方向跟电流一致。正转就从力矩里减掉 ff。反转时减掉负的 ff，等于往正方向加 ff。效果都是和转动方向相反。停住时这项是 0。

目标角大于当前角时，电压为正，电流偏正。力矩把角度往目标方向推。转得越快，反电动势和摩擦都来拆台。

力矩和转动惯量从哪来

力矩是这一下的拧劲。转动惯量是转起来有多沉。

推门时，同一股力离轴越远，门越容易转开。τ=Fℓ\tau=F\ell。单位是牛·米。公式里的 τ\tau 就是舵机轴上的这份拧矩。

直线推动用 F=maF=ma。转动时还要看质量离轴多远。同一公斤，伸得越远越难转起来。一个质点写成 I=mr2I=mr^2。单位是 kg⋅m2\mathrm{kg\cdot m^{2}}。

Iθ¨=τI\ddot\theta=\tau。这是转动版的 F=maF=ma。玩具代码里 I=0.01I=0.01，是算例用的替身。

BAM 是手册定义的，还是实验拟合的

XL330 的手册没有定义 BAM。microduck 也没有自己做辨识实验。

BAM 是 Rhoban 的库。他们把真 XL330 装在摆上。摆的质量和杆长要换几组。录下 240 段曲线，每段 6 秒。拟合之后得到模型。m6 是摩擦公式最全的一档。

ROBOTIS e-Manual 写的是寄存器、额定电压和堵转力矩。选实验用的 P 增益时会参考手册。模型文件是拟合结果。

教程背景卡片里的 Kt=0.08K_t=0.08、R=1.5R=1.5、摩擦 0.0150.015，用来把链条念出来。库里的 m6.json 是另一套数。

真舵机分两层。固件位置环把角度差变成电压指令。电机本体还有电压封顶、反电动势、减速箱惯量，以及随负载变化的摩擦。

MuJoCo 的 position 执行器把这两层收成一根弹簧。训练时策略看到的是 BAM 那条链。Bite 5 在弹簧家族里试过 kp=8k_p=8、4040 和 0.550.55。坐和前滚翻都没有回到训练时的响应。
