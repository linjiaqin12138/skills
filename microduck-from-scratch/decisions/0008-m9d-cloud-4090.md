## 上下文

M9 算力原定 Vast.ai RTX 5090。用户开了国内云机 **RTX 4090**（按量，系统盘 70GB + 数据盘 100GB），镜像预装 `torch 2.1.3` / 旧 CUDA toolkit 标签，与 microduck_rl 锁版 **`torch==2.9.1` + Python 3.12 + uv** 冲突。本 Bite 要在真 GPU 上完成环境搭建与官方冒烟（64 envs × 5 iter），为后续首训铺路。

## 备选

1. **换卡不换栈**：继续用官方 `uv sync` 拉 `torch==2.9.1`（wheel 自带 CUDA runtime）；忽略镜像里的系统 PyTorch；代码与数据落在数据盘；GPU 用 4090，OOM 时把 `num-envs` 从 4096 降到 2048/1024。
2. **死磕 5090**：释放 4090，等/换 5090 再训（官方主机是 5090）。
3. **迁就镜像**：在镜像自带 torch 2.1.3 上硬跑，改 microduck_rl 依赖。

## 决定

采用备选 1。理由：MicroDuck 小模型 + MuJoCo Warp 在 4090 24GB 上可训；管线锁版不能破；镜像只当「Ubuntu + 驱动」，环境以 uv 为准。

## 放弃的成本

备选 2 与官方主机同卡，少踩 Blackwell/Ada 差异；放弃它的代价是冒烟/首训可能略慢（约 1.3–1.7×），以及要自己处理 24GB 显存上限。

备选 3 能少装一次依赖；放弃它的代价是与官方配方分叉，后续 export/manifest/推理全不可对账。

## 失效边界

4090 在冒烟或 `num-envs≥1024` 首训上持续 OOM，且降到无法完成「可用步态」预算时，改回 5090/32GB 或换更大显存卡。
