# 概念 HTML 教程与 concept-writer 子代理改造方案

> 状态：P0（职责拆分与验收门）已于 2026-10-21 实施——新增 `concept-writer-subagent.md`，`writer-subagent.md` 概念规则改为路由条款，`SKILL.md` 增加调度与三层验收；教程页面尚未按新流程重写（P1 起）。
>
> 维护约定：本文作为后续讨论的单一沉淀文档。有新结论时补充本文，并同步修订相关正文，避免只追加日志而让正文与结论互相矛盾。「已确认方向」与「建议方案」分开记录。

## 1. 背景

对 `microduck-from-scratch/docs/concepts/` 的页面做了定向诊断：实际打开并定格检查四元数动画，抽查惯量张量、接触穿透、舵机交互和 M9 教程源稿。

结论不是简单的“图不够漂亮”或“术语太多”，而是当前写作流程更容易生成**知识点资料页**，不一定能生成**读者可以独立学会的概念教程**。

### 1.1 已观察到的症状

- 四元数页没有先建立“一个具体旋转怎样表示为四个数、怎样作用到向量”的最小心智模型，就进入 `S³`、双覆盖、复合和插值。
- “打包”“投影”等词没有明确的操作定义；球面、坐标轴、蓝点和左右轨迹的含义需要读者猜。
- 动画只展示结论，没有暂停、关键帧、当前变量值和明确的面板对应关系。
- 惯量页说“非对角元消失”，图里却没有矩阵及坐标变换的对应。
- 接触页的部分几何和力的方向与要解释的物理关系不一致。
- 自测主要考工程坑和正文可直接找到的结论，没有覆盖核心图和核心心智模型。
- 外部素材链接实际上成了理解页面的前置条件。

### 1.2 流程根因

当前规范主要保证：

- 有固定章节；
- 有图、有动画、有代码；
- 页面能渲染，动画能播放；
- 有 3～5 道自测题。

这些是交付物的形式检查，不是理解检查。

`skills/clone-from-scrach-tutor/writer-subagent.md` 同时承担里程碑教程与概念深读页两类任务。两者需要不同的工作方法：

- 里程碑教程：问题 → 背景 → 设计 → 代码领读 → 验收。
- 概念教程：确定理解断点 → 建立最小模型 → 可视化关系 → 形式化 → 预测与验证。

职责混在同一份长提示词里，既增加上下文负担，也让里程碑教程的固定结构泄漏到概念页中。

## 2. 已确认方向

1. 概念 HTML 文档需要针对“读者仍然看不懂、图解无法独立解读”的问题进行系统改造，而不是逐张图零补丁式修饰。
2. **概念文档的编写职责应从原 writer 中拆出，交给独立的 concept-writer 子代理。**原 writer 的提示词已经较长，不应继续承担完整的概念教学规范。
3. 提示词拆分（P0）已实施；页面重写（P1 起）和按新流程的修订仍需后续实施。
4. 后续讨论形成的新结论继续补充到本文。

## 3. 改造目标与边界

### 3.1 核心目标

把 Agent 的交付目标从：

> 生成一份知识点齐全、图会动、代码能跑的 HTML。

改为：

> 让目标读者不依赖外部讲解、不阅读实现源码，只使用本页，就能完成几项明确、可观察、可检查的理解任务。

“知识点写到了”“图片显示了”“代码运行了”都不等于“读者理解了”。

### 3.2 不应改变的有效工程约束

以下现有规则应保留，除非后续另有明确结论：

- `.draft.md` 是源稿，HTML 由 `bin/am-render` 整页生成，不手改产物。
- 示例和事实必须核实，禁止编造。
- 自制素材落在对应 `assets/` 目录，页面使用相对链接。
- 中文表达直接、简洁，代码标识符保留原样。
- 概念页与里程碑背景卡片各司其职：概念页讲概念本身，里程碑页说明它在项目中的用途并链接深读页。
- 浏览器技术验收仍需执行，但不能作为唯一验收。

### 3.3 非目标

- 不追求每页固定数量的图、动画、代码或面板。
- 不用更多类比、更多段落或更炫的动画代替心智模型建设。
- 不把外部视频当作页面能够交付的隐含前提。
- 不在规范拆分阶段顺手重写全部历史页面。

## 4. 独立 concept-writer 子代理方案

### 4.1 必须是职责拆分，不只是文本搬家

建议新增：

`skills/clone-from-scrach-tutor/concept-writer-subagent.md`

它不仅存放独立提示词，还对应一次独立的子代理执行。

如果只是把概念规范移动到另一个 Markdown 文件，却仍要求原 writer 阅读并兼任概念作者，只能缩短部分静态文本，不能解决职责冲突和理解验收缺失。

### 4.2 职责划分

#### 主 agent

- 汇总各阶段会用到的概念清单（每个配一句话定义），交用户标记熟悉度，按用户自报决定是否需要概念深读页。
- 收集读者疑问、前置背景、事实材料和输出路径。
- 准备完整的概念任务包，调用 concept-writer。
- 组织独立冷读与最终验收，不代替子代理补写整页。

#### 里程碑 writer 子代理

- 只负责里程碑教程、背景卡片、项目映射和链接。
- 不再亲自编写完整概念深读页。
- 写作中如果发现需要新增或修订概念页，返回明确需求，由主 agent 调度 concept-writer，避免两个作者同时改同一页面。

#### concept-writer 子代理

- 负责概念页的教学设计、源稿、图示或交互、示例、自测和浏览器检查。
- 默认只拥有 `docs/concepts/<slug>.draft.md`、对应 HTML 和 `docs/concepts/assets/<slug>/` 的写作职责。
- 不修改里程碑正文，不修改项目实现代码。
- 若发现事实、代码或数据本身有问题，报告并请求核实，不用文案掩盖。

#### verifier / 冷读评审

- verifier 继续负责可运行示例、命令、输出和事实性检查。
- 理解冷读应尽量由未参与写作的独立评审者执行，不能把作者自检当作真正的冷读。
- 初期可以按任务临时调用一个无源稿上下文的评审子代理，不必立即再维护一个长期、庞大的 reviewer 提示词；确有重复需求后再决定是否固化角色。

### 4.3 推荐调度方式

属于某个 Bite 的概念页，原则上在里程碑 writer 成稿前完成，使背景卡片可以链接到真实页面：

```text
主 agent 识别概念需求
  → 准备概念任务包
  → concept-writer 产出页面与理解验收卡
  → 独立冷读 / 技术验证
  → 必要时退回 concept-writer 修订
  → 里程碑 writer 写背景卡片并挂链接
```

concept-writer 与架构 diagram 子代理通常可以在事实材料齐备后并行；里程碑 writer 不应与 concept-writer 共同拥有同一个概念文件。

已有概念页收到读者困惑反馈时，可直接进入 concept-writer 的修订流程，不必重跑整个 Bite。

### 4.4 concept-writer 的输入任务包

主 agent 至少应提供：

- 目标读者：已经知道什么，默认不知道什么。
- 触发问题：读者在哪一句话、哪张图或哪个操作上卡住。
- 核心问题及内容边界。
- 已核实的概念事实、公式、代码、实验输出或素材路径。
- 概念与项目的关系，供作者理解使用场景；是否写进概念页仍遵守概念页边界。
- 输出文件和素材目录。
- 用户已明确提出的学习目标或必须解决的误解。
- 需要遵守的用户偏好文件路径。

缺少关键事实时应先索取或调查，不得让子代理用通用知识猜项目事实。

### 4.5 concept-writer 的返回物

除页面文件外，返回一份简短的教学交付说明：

- 核心问题；
- 读者看完后应能完成的 1～3 项任务；
- 每张图分别承担的教学任务；
- 最容易误读的地方及对应处理；
- 自测与理解目标的对应关系；
- 已运行的命令、浏览器关键帧检查结果；
- 仍存在的边界或未验证事项。

这份说明用于验收，不意味着要在教程页面里再增加一个形式化面板。

## 5. concept-writer 提示词应包含的教学规范

### 5.1 先写教学合同，再写 HTML

动笔前必须明确：

- **目标读者**：前置知识和经验边界。
- **核心问题**：本页只回答一个核心问题。
- **理解结果**：读者完成后能独立完成的 1～3 项任务。
- **易误读点**：读者可能把什么看成什么，页面如何主动消除。
- **内容边界**：哪些高级内容不是核心理解所必需，应后置、折叠或拆页。

理解结果必须可观察，例如：

- 根据具体输入预测输出；
- 指出图中各符号、轴、点和轨迹的含义；
- 解释两个表示为什么等价；
- 判断一个常见说法为什么不成立。

不能只写“了解 X”“掌握 X”“建立直觉”。无法写出理解结果时，不直接生成 HTML。

### 5.2 用学习链代替固定章节模板

当前的“一句话版本 → 为什么需要 → 最小代码 → 素材 → 自测”降为可调整的表达素材，不再是所有概念必须机械套用的顺序。

默认学习链为：

```text
具体对象或问题
  → 足够简单、可以人工检查的实例
  → 用图或交互建立变量关系
  → 引入一般定义、公式和术语
  → 预测一个新情况并验证
  → 工程边界、常见坑与参考资料
```

具体要求：

- 先回答“它是什么、它做什么”，再比较其他方案。
- 核心理解必需的推导不得藏进折叠区或外部链接。
- 一页只建立一个核心心智模型；不服务于该目标的复合、插值、优化和高级理论应后置或拆页。
- 新术语首次使用时就地解释，文末术语表不能替代就地解释。
- 类比可选，不替代定义；使用后必须说明边界。
- 外部素材只用于复习或拓展，不能成为理解本页的前置条件。

### 5.3 每张图必须有图解合同

画图前先回答：

> 读者看完这张图，应该能说出或预测什么？

答不出来就删图，而不是为了“必须有图”保留装饰。

涉及空间、状态或变量关系的图，应按需要明确：

- 画的是实物、坐标系、参数空间还是数据结构；
- 观察方向和视角；
- 坐标轴、单位和维度；
- 点、线、颜色和箭头的含义；
- 输入与输出的对应；
- 哪些部分按比例，哪些只是符号化表达。

“图内文字极简”只限制无关段落，不得删掉理解图形所必需的标注。多个面板联动时，必须说明共享变量和同步关系。

#### 投影与高维示意

- 使用“投影”时，必须说明从什么空间到什么空间、保留什么、舍弃什么、屏幕方向对应什么。
- 无法定义上述映射时，不得写“投影”。
- 如果精确的低维切片足以解释问题，就画低维切片，不使用未定义的高维球体投影增加负担。
- 仅作象征的图必须明确标注“符号示意，不用于读取几何关系”，且不得承担核心证明或推导。

### 5.4 动画必须支持观察和推理

- 动画必须回答一个明确问题，而不只是让元素运动。
- 自动循环不能是唯一观察方式；需要比较多个状态时，提供暂停、重播、逐帧或变量滑块。
- 给出关键状态的静态帧、当前变量值和必要结论。
- 首帧必须可读，不能要求读者先追上动画才能理解图例。
- 验收首帧、中间帧和关键帧的含义与数值，不能只检查元素是否变化。
- 如果静态分帧更适合来回比较，就使用静态分帧，不强行做动画。

### 5.5 示例与代码必须证明当前结论

- 优先选择能心算、手算或直接观察的输入。
- 每组输出只承担一个明确观察任务，并告诉读者应该看哪里。
- 不把多个新概念塞进同一个“最小示例”。
- 人为注入缩放、噪声或扰动时，必须明确实验条件，不能把它包装成自然现象的证明。
- 代码可运行是必要条件，但不能替代概念解释。
- 如果图示或交互更适合建立当前概念，允许先不放代码。

### 5.6 自测必须对齐教学合同

- 每项核心理解结果至少有一道对应检查。
- 至少包含一项读图或预测任务，不能全部考工程坑和术语记忆。
- 读者不能仅靠复制紧邻上文的句子完成全部题目。
- 解析必须解释依据，而不只是宣布正确选项。
- 如果读者能答对全部自测，却仍无法解释核心图，说明自测设计不合格。

## 6. 理解验收方案

### 6.1 三层验收

1. **技术验收**：页面渲染、资源链接、脚本运行、交互操作、控制台错误、不同窗口尺寸。
2. **语义验收**：图中对象、方向、坐标、数值和因果关系与概念一致；首帧、中间帧和关键帧都检查。
3. **理解验收**：未参与写作的读者只使用 HTML，能够完成教学合同中的任务。

三层不能互相替代。

### 6.2 冷读流程

独立评审者不看源稿、不看实现源码、不打开外部素材，只打开 HTML：

1. 指出每张图的轴、点、颜色、轨迹和视角。
2. 解释多个面板之间的对应关系。
3. 完成页首承诺的预测或解释任务。
4. 尝试自测，并检查自测是否真正覆盖核心理解。

失败后先分类，不直接追加更多文字：

- 缺前置知识；
- 图形符号没有定义；
- 实物空间、参数空间或多个变量混淆；
- 示例不能支持结论；
- 页面一次承载太多目标；
- 事实或图形关系本身有误。

按断点重写对应环节。禁止只在图后再补一段更长的解释，然后宣布完成。

**成本控制（2026-10-22 P1 试点沉淀）**：冷读只回答上述任务清单，证据从简（每张图一张截图即可）；控制台、深色模式、窄视口等技术检查归 §6.1 技术验收，不进冷读；修订后的复验按改动半径缩放，不重跑全量。退回修订时必须附已通过项清单，修订不得回退已通过项。

### 6.3 父级流程必须同步

只拆 `concept-writer-subagent.md` 还不够，还需在实施时同步：

- `skills/clone-from-scrach-tutor/SKILL.md`：增加 concept-writer 的调度、输入、返回和理解验收职责。
- `skills/clone-from-scrach-tutor/writer-subagent.md`：删除完整概念写作规范，只保留背景卡片、项目链接和“概念页交给 concept-writer”的短路由条款。
- 当前“面板非空、图在显示、动画在动、自测存在”的主 agent 抽查条款，升级为技术、语义、理解三层验收。

概念教学的详细规则只由 `concept-writer-subagent.md` 持有，父级文件只保留调度与验收门，避免多份规范再次漂移。

## 7. 用现有页面作为提示词的回归测试

### 7.1 四元数

新概念页至少应做到：

- 先用固定 z 轴旋转 90° 的具体例子，说明四个数怎样表示旋转，以及输入、输出向量是什么。
- 双覆盖先固定转轴，利用 `x=y=0` 画精确的二维 `(w,z)` 圆，不再让未定义的球体“投影”承担核心讲解。
- 左图明确“俯视图、z 轴指向屏幕外”，并解释物体、旋转轴和标记点。
- 提供角度滑块或逐帧控制，以及 `0°、180°、360°、720°` 关键帧和当前数值。
- 先建立 `q` 怎样作用到向量，再解释 `q` 与 `-q` 等价；720° 是后续例子，不是入门起点。
- `S³`、一般转轴、复合和插值后置或拆页。
- 修正“归一化漂移”示例：当前脚本人为给每步乘 `1.001`，不能用输出直接证明通常浮点连乘的自然漂移。

> 修订（2026-10-22，读者反馈）：上面把“定义、每个量的含义、四则运算”也一并后置了，这是误判——它们是读者的第一心智模型，不是高级内容。读者反馈“定义没讲清、每个量的含义没搞明白、整一堆代码和动画”后，页面已重构为：定义（i,j,k 乘法表）→ 每个量的含义 → 四则运算（Hamilton 积、共轭、范数、逆）→ z 轴实例 → 旋转作用 → 双覆盖，冷读通过。真正可后置的只有：任意转轴的旋转证明、复合顺序、插值、S³ 整体几何。

### 7.2 惯量张量

- 同一刚体、两种坐标系和两份矩阵同屏对应。
- 明确旋转矩阵及主轴朝向表示什么。
- 图、公式和 NumPy 输出使用同一个具体对象，不让代码输出代替视觉解释。

### 7.3 接触穿透

- 地板、盒子、穿透量、接触点和作用力的几何关系必须一致。
- 用局部放大图表达压缩量和向上作用力。
- 区分一般接触模型、MuJoCo 的具体实现和为了可视化做的夸张，不把特定求解器模型说成所有物理引擎的唯一实现。

### 7.4 保留舵机页的有效做法

- 明确多个对照对象；
- 标明控件作用于哪个对象；
- 解释目标线、颜色和其他视觉编码；
- 让读者能操作一个变量并预测结果。

这些做法应沉淀为原则，而不是要求所有页面照搬三臂布局。

## 11. 后续讨论结论记录

### 结论 1：概念编写需要独立子代理

- **结论**：概念文档不再由原里程碑 writer 兼任，使用独立 concept-writer 子代理。
- **原因**：原提示词已经较长；两类文档的教学结构和验收方式不同；仅移动文本不能解决职责冲突。
- **影响**：需要同时调整父级调度、原 writer 路由条款和理解验收，不是只新增一个提示词文件。
- **实施状态**：已实施（2026-10-21，P0 完成：新增 `concept-writer-subagent.md`，writer 改为路由条款，SKILL.md 增加调度与三层验收）。

### 结论 2：验收成本需要治理（P1 试点复盘）

- **结论**：concept-writer 交付前必须过机械自查清单；冷读只答任务清单、证据从简；退回修订必须附已通过项清单、不得回退；写作类子代理用主模型，检验/评审类可用轻量模型。
- **理由 / 证据**：P1 总 wall time 约一小时。MiniMax 首跑 12.5 分钟死于提供商 400，整轮作废；两轮冷读各约 11 分钟，大头是浏览器截图往返；第一轮冷读抓到的"D 图无图例、自测 5/5 可抄正文"本可由作者自查拦下；第一轮修订把双覆盖自测覆盖改丢了，因为退回时没列已通过项。
- **对方案的影响**：§5 规范增加「交付前自查清单」（落在 concept-writer-subagent.md）；§6.2 增加成本控制段；SKILL.md 的退回流程附已通过项、冷读限范围、复验按改动半径缩放、增列子代理模型建议。
- **实施状态**：已实施（2026-10-22，concept-writer-subagent.md 与 SKILL.md 已同步）。

### 结论 3：内容边界的"后置"判定要以读者的第一心智模型为准（P1 二轮修订）

- **结论**：定义、每个量的含义、基本运算不是可后置的"高级内容"，是概念的第一心智模型；只有证明、复合、插值、整体几何这类才后置。§7.1 已同步修订。
- **理由 / 证据**：P1 页面按"特例优先、一般形式后置"交付后，读者（用户）反馈"没有讲清楚定义、四则运算，每个量的含义没搞明白，整一堆代码和动画"。补入定义/含义/运算三面板重构后，冷读者可独立写出定义、复现乘法表、手算乘积并对照 Hamilton 公式，自测扩到 8 题全覆盖，冷读通过。
- **对方案的影响**：§7.1 的边界清单已修正；concept-writer-subagent.md 教学合同的「内容边界」条目增列判定原则（定义/分量含义/基本运算不可后置）。
- **实施状态**：已实施（2026-10-22，页面重构 + 冷读通过 + 规范同步）。

### 结论 4：概念页按用户自报的熟悉度产出，不替读者假设（2026-10-22）

- **结论**：背景卡片与概念页由"用户熟不熟"驱动——Phase 2 随里程碑计划附概念清单（每个配一句话定义）交用户标记；已熟的不插卡，不熟的插卡，不熟且关键的才出概念页。写作中途遇到计划外概念、或用户反馈"看不懂"，随时补问补出。
- **理由 / 证据**：用户指出 tutorial 侧负担太重——按领域统一生产概念内容，会为用户已懂的概念写卡片和页面。自报的风险（不知道自己不懂）用两条兜底：询问时给一句话定义供对照，不只报名词；"看不懂"反馈通道常开。
- **对方案的影响**：§4.2 主 agent 职责第 1 条已改为"汇总概念清单交用户标记"；SKILL.md 铁律 3、Phase 2（概念熟悉度闸门）、Phase 3 第 4 步调度条件、writer-subagent.md 的背景卡片与通俗引入条款同步修改。
- **实施状态**：已实施（2026-10-22）。
