# 通用 GUI Agent 与「学任意软件」调研

> 调研日期：2026-11-04  
> 需求：希望用 AI 教自己操作任意桌面软件（Photoshop、Premiere、CAD、Figma 等皆可作例子），在真实 GUI 里复刻流程。已知问题：AI 对文本/图片强，对 GUI 弱；浏览器自动化遇到 canvas 内控件几乎不可用。硬约束：**要能在 Ubuntu 与 Windows 上运行**（Mac-only 方案仅作对照，不作主推荐）。  
> 资料来源：产品官网、GitHub / skills.sh、厂商帮助文档、arXiv / 基准论文与公开排行榜。**未逐一手动安装验证**；平台与成功率描述以公开文档与论文自述为准，落地前需自测。

---

## 结论

1. **「教软件」与「代点 GUI」是两条产品线，不要混用期望。**  
   - **Tutor（指点）**：看屏 → 指/高亮下一步 → **人点击**。适合学会。  
   - **Computer-Use Agent（代点）**：截图 / 无障碍树 → **Agent 自己点鼠标键盘**。适合自动化；长程专业软件仍脆。

2. **成熟屏上教学产品高度偏向 Mac。** Skilly、Pointy、Alfred、Roger 等体验最好的一批目前基本是 macOS。在 **Ubuntu + Windows** 约束下，公开信息里较接近「学任意软件」的是：  
   - **Glowbug**（宣称 Win / Mac / Linux，指点不代点）  
   - **DuckyHelper**（宣称三端，看屏+画标注）  
   - **Cadet**（Win/Mac/Linux 可用 Chrome/Edge 浏览器版共享窗口指点；桌面安装包主要是 Win/Mac）  
   - Windows 可加 **HeyBraza**（无 Linux）

3. **真正跨 Win + Ubuntu 的「通用 GUI」底座，主要是开源 computer-use，不是教学 App。**  
   优先关注：**Agent-S（`gui-agents`）**、**Cua Driver**（AT-SPI / UIA + 截图）。Claude Desktop 的 **Computer Use 在 Linux 上官方不可用**（仅 Mac/Windows）。UI-TARS Desktop **官方不支持 Linux**。

4. **Canvas / 时间线 / 视口自绘 UI 仍是系统短板。** Browser DOM/CDP（含 agent-browser）读不到 canvas 内按钮；专业后期基准 CutVerse 整体成功率约 **36%**；通用桌面基准早期常在 **~12%–20%** 量级（后续 Agent-S 等报更高分数，多含 Best-of-N 或专用 grounding，落地成本不同）。

5. **本仓库现有教学 Skill（learn-coach、explain-it、clone-from-scratch-tutor、make-video 等）擅长讲概念与代码复刻，不擅长接管任意软件 GUI。** 网上与「教学 + GUI」最接近的 skill 形态是 **Skilly 式 `SKILL.md` 课程**（阶段、UI 词表、完成信号），但是 Mac 产品；可作未来自研 Tutor skill 的参照，不能直接当 Ubuntu/Windows 运行时。

6. **落地建议（硬约束下）：**  
   - **学任意软件**：Glowbug / DuckyHelper / Cadet 浏览器版（+ Windows 上 HeyBraza）；固定「人点、AI 指」。  
   - **需要 Agent 动手或接 Cursor**：Ubuntu/Windows 上装 **Cua Driver** 或 **Agent-S**；预期 Office/设置尚可，PS/Premiere/CAD 画布仍易偏。  
   - **有 API/脚本时优先 API**（Fusion MCP、FreeCAD Python、OpenSCAD/build123d 等），GUI 只作缺口与验收。

## 1. 问题界定

| 维度 | 说明 |
|---|---|
| 目标用户行为 | 在真实软件里跟着学会操作，而不是只看视频或只拿文本步骤 |
| 软件范围 | **任意桌面/创意软件**（剪辑、PS、CAD、设计工具等）；CAD 仅作早期举例，不是调研边界 |
| 技术卡点 | 控件常在自绘 canvas / OpenGL / 时间线中，无稳定 DOM；浏览器自动化失效 |
| 平台硬约束 | **Ubuntu + Windows** 都必须可用；Mac-only 只登记、不主推 |
| 非目标 | 单独做 CAD 内核开发、单独做 Text-to-CAD 消费产品选型（文中仅作相关旁路） |

## 2. 两条路线：Tutor vs Computer-Use

```text
用户目标：「学会用这个软件」
                │
        ┌───────┴───────┐
        ▼               ▼
   Tutor 指点      Computer-Use 代点
   看屏+高亮         截图/AX+键鼠
   人执行点击         Agent 执行点击
   肌肉记忆留下       任务完成即可
```

| | Tutor | Computer-Use Agent |
|---|---|---|
| 成功标准 | 用户下次能自己点 | 任务状态可验收 |
| 对 canvas | 仍难准确定位，但失败时人可纠偏 | 误差易滚雪球 |
| 安全/权限 | 录屏；通常不接管输入 | 录屏 + 键鼠注入；应用权限敏感 |
| 与 Agent Skill 关系 | 课程式 `SKILL.md`（如 Skilly） | 驱动式 skill（cua-driver、peekaboo、computer-use） |

业界共识（多份文档与论文表述一致）：

1. 有 API / 脚本 → 用 API  
2. 有无障碍树（AX / UIA / AT-SPI）→ 按元素点  
3. 纯 canvas → 像素 computer-use（慢、脆）  
4. **教学场景优先指点，不代点**

### 3.2 教学 Skill 形态（参照，非本机默认）

**Skilly**（开源，Apache-2.0，fork 自 Clicky）是目前公开资料里最清晰的「GUI 教学 + Skill」结合：

- 每个 App 一份 `SKILL.md`：课程阶段、完成信号、UI 词汇表  
- 自带示例：Blender / After Effects / Premiere / DaVinci / Figma basics  
- 另有 [Skill Builder](https://tryskilly.app/tools/skill-builder/) 可生成可导入课程  
- **运行时仅 macOS** → 对本文硬约束：可作 **自研 Ubuntu/Windows Tutor skill 的规格参考**，不能直接安装使用

Claude Cowork 的 **Record a Skill**（录屏操作 → 生成可复跑 skill）偏 **自动化复现**，不是「教你学会」；且 Desktop Computer Use 在 **Linux 不可用**。

### 3.3 垂直软件内 Tutor（举例，非通用）

| 产品 | 软件 | 平台要点 |
|---|---|---|
| CADABRA / CAD Helper / MecAgent | SOLIDWORKS 等 | 多为插件；Windows 为主 |
| Cizgen Tutor | AutoCAD | 读图纸几何差分纠错，非纯截图 |
| Onshape AI Advisor | Onshape | 文档接地问答；不生成模型 |

这类产品验证了「读模型树 / 几何」优于「盲点 canvas」，但无法覆盖「任意软件」。

### 4.3 可装的「驱动型」Agent Skill（skills.sh 生态）

偏操作契约，不是「Premiere 入门课」：

| Skill / 包 | 平台倾向 | 要点 |
|---|---|---|
| `cua-driver`（trycua/cua） | Win / Mac / Linux | snapshot → `element_token` → 验证；像素兜底 |
| `desktop-control`（factory-ai） | 经 cua | Electron 仍建议走 CDP/browser，不走纯 a11y |
| `notis-desktop-use` / `peekaboo` | **Mac** | Ubuntu/Windows 排除 |
| `agent-native` | **Mac** | AX 树，类比 agent-browser |
| `winapp-ui-automation`（Microsoft winappcli） | **Windows** | UIA；Ubuntu 排除 |
| Hermes / Superset `computer` / `computer-use` skill | 视宿主 | 强调 stale token 拒绝、动作后重捕获 |

**原则：** Electron/Chromium 桌面应用优先 CDP（agent-browser）；真原生控件走 a11y；canvas 只能视觉坐标。

## 5. 能力边界与基准证据

### 5.1 为何 browser agent 不够

- DOM/CDP 只能看见 HTML 控件；**canvas 绘制的工具条、时间线、草图区没有可靠节点**。  
- 社区 issue（如 canvas 渲染的在线表格）反复确认：浏览器层只能看到 chrome，格子/画布内容需退回像素路径。  
- 本仓库 `agent-browser`：强于网页与部分 Electron；**不适合作为「学任意专业软件」的主执行器**。

### 5.2 通用桌面基准（量级）

| 基准 | 内容 | 公开结果（量级） |
|---|---|---|
| [OSWorld](https://osworld-v1.xlang.ai/) | 真实桌面多 App 任务 | 早期最强约十余百分点；后续 Agent-S 等报更高（含 BoN 等设定） |
| [WindowsAgentArena](https://microsoft.github.io/WindowsAgentArena) | Windows 多域任务 | 早期 Navi 约 **19.5%** vs 人约 **74.5%**；媒体类（如 VLC）偏难 |
| Anthropic / OpenAI 早期 OSWorld 数字 | 通用 computer use | 远低于人类约 70%+ 水位 |

解读：即使用「通用 GUI agent」，也远未到「可靠陪你复刻任意专业软件」的产品水位；教学场景更应让人掌控点击。

### 5.3 专业创作软件基准

| 基准 | 内容 | 公开结果（量级） |
|---|---|---|
| [CutVerse](https://arxiv.org/html/2605.19484) | Premiere / PS / AE 等后期长程任务 | 整体约 **36%**；Premiere/PS/AE 各模型约 **40%–66%** 区间 |
| [CADWorld](https://cad-world.github.io) | FreeCAD 长程工程任务 | 最强 agent 约 **17.5%** vs 专家约 **87%** |
| [CAD-CUA](https://spacetimeml.com/papers/SpacetimeML-CAD-CUA-Technical-Report.pdf) | 蓝图 → B-Rep，多款 CAD | 前沿模型 Pass@1 约 **10%–15%**；人 100%。失败含视口、孔系遗漏、非流形、硬编码坐标 |
| [GUI-EDA](https://arxiv.org/html/2512.11611) | 专业 EDA/CAD GUI | 标为现有 GUI agent 最弱域之一 |
| [Cua-Bench](https://cua.ai/cuabench/report)（KiCad） | EDA 原理图 | 最好约 **6/25**；从空白可靠搭完整电路未观察到 |
| VideoCAD（MIT） | Onshape 操作视频学习 | 研究向 co-pilot；非通用 Cursor skill |

常见失败模式（CAD-CUA 等归纳，对剪辑/PS 亦有类比）：

1. 视口 / 6DoF 导航失败  
2. 正交视图与轴向混淆  
3. 内部细节（孔系、关键帧）遗漏  
4. 参数不可编辑、硬编码坐标  
5. 长程步骤误差累积

## 6. 旁路：API / 脚本 / Text-to-CAD（有 API 时优于 GUI）

当目标软件暴露脚本或 MCP 时，**复刻结果**应走这条，GUI 仅用于人学菜单或视觉验收：

| 路线 | 例子 | 与 GUI 教学关系 |
|---|---|---|
| 本地 Code-CAD | OpenSCAD skill、build123d / [earthtojake/text-to-cad](https://github.com/earthtojake/text-to-cad)、agentcad-skill | AI 写代码出零件；人对照学 GUI |
| CAD MCP | FreeCAD MCP、Fusion 官方 MCP、[fusion-cad-mcp](https://github.com/Mfrostbutter/fusion-cad-mcp) | Agent 改模型；Autodesk 自述复杂草图仍不可靠 |
| 厂商自动化 | APS Design Automation、各家 COM/Python API | 批处理强；教学弱 |
| Blender 对照架构 | Blender MCP + 截图校验；Computer Use 只做导航/目检 | **最清晰的「API 动手 + 视觉验收」模板**，可类比到其它软件 |

本仓库相关：`learn-coach` / `explain-it` 可教概念；`clone-from-scratch-tutor` 面向开源代码手搓，**不是**任意 GUI 软件 Tutor。

## 7. 硬约束下的推荐矩阵

| 你的目标 | Ubuntu | Windows | 不推荐 |
|---|---|---|---|
| **学任意软件（主路径）** | Glowbug / DuckyHelper / Cadet 浏览器 / Blinky（DIY） | 同上 + HeyBraza | Skilly、Pointy、仅 Mac Tutor |
| **Agent 代点本机 GUI** | Agent-S、Cua Driver、自建 Computer Use 沙箱 | 同上 + Claude Desktop Computer Use | 指望 agent-browser 点 PS/Premiere canvas |
| **接进 Cursor / Claude Code** | `cua-driver` skill + 本机 daemon；或 Agent-S CLI | 同左；Win 可加 UIA 工具 | Linux 上开 Claude Desktop Computer Use（官方无） |
| **有 API 的软件复刻结果** | 对应 MCP/脚本 skill | 同左 | 纯像素长程代点作为主路径 |
| **自研「教学 Skill」** | 抄 Skilly `SKILL.md` 规格 + 跨平台指点壳（Glowbug 类或自研 overlay） | 同左 | 把 computer-use 成功率当教学完成度 |

### 建议试用顺序

1. 在 Ubuntu 与 Windows 各装 **Glowbug**（或 DuckyHelper），用同一软件（如 GIMP / LibreOffice / 浏览器 DevTools）测「指点是否准、延迟、隐私」。  
2. 若需课程结构：用 Skilly 公开的 `SKILL.md` 作模板，自写「任意 App」课程文件，挂到自选 Tutor 壳（或未来自研）。  
3. 若需自动化演示：在 **X11/XWayland** Ubuntu 与 Windows 上装 **Cua Driver**，先只测计算器/系统设置，再测目标专业软件，记录 a11y 树是否暴露工具栏。  
4. 专业软件若存在 Python/API：并行开脚本路径；GUI Tutor 只负责「菜单在哪」。

## 8. 缺口与可跟进问题

| 缺口 | 说明 |
|---|---|
| Ubuntu 原生「屏上教学」产品稀缺 | 多数精品 Tutor 先做 Mac；Glowbug/DuckyHelper 等需实机验证稳定性与隐私条款 |

| 本仓库无对应 Skill | 现有 explain/learn 不覆盖「任意软件 GUI 指点」；若产品化需新建 skill + 运行时依赖说明 |
| 基准与营销数字 | Agent-S OSWorld 高分常含多次采样或专用 grounding；产品承诺应低于论文峰值 |

**建议后续验证实验（未做）：**

1. Ubuntu 22.04/24.04 + Windows 11：Glowbug / Cadet 浏览器版各跑 10 个「任意软件」任务，记录指点命中率。  
2. 同一台机：Cua Driver 对 GNOME Calculator vs GIMP 工具栏 vs 浏览器 canvas 应用的元素可见性对比。  
3. 若自研：一份最小 `teaching-gui` skill 规格（阶段、UI 词表、完成信号、禁止代点）+ 平台驱动适配表。

## 10. 一页纸摘要

**问题：** AI 如何在真实 GUI 里教人用任意软件？浏览器 canvas 与专业软件自绘 UI 使 DOM 自动化失效。  
**分型：** Tutor（指点）≠ Computer-Use（代点）。学软件选前者。  
**平台：** Mac Tutor 最成熟；**Ubuntu+Windows** 下优先 Glowbug / DuckyHelper / Cadet 浏览器；驱动层用 Agent-S / Cua Driver。Claude/UI-TARS 桌面控屏在 Linux 侧缺口明显。  
**证据：** 专业创作与 CAD GUI 基准显示成功率仍低；API/脚本路径更稳。
