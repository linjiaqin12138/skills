A

一句话版本

IDT 是一张 256 行的跳转表，向量号就是行号。

CPU 发生异常或收到中断时读取对应行。门描述符给出 handler 地址和代码段选择子。

跳转前，CPU 把 RIP、CS、RFLAGS 等字段压栈。部分异常还会多压一个 error code。

RFLAGS 是 64 位标志寄存器。

IOPL 占两位。图中 0 表示保留位读取为 0。bit 1 是保留位，但读取为 1。

B

异常与中断

三种来源共用 IDT，但触发时机不同。

来源 触发者 例子 与当前指令的关系
异常 CPU 检查指令执行 #DE、#UD、#PF 同步
外部中断 CPU 之外的设备 定时器、键盘 异步
软件中断 程序主动执行 int n 约定的服务入口 由程序主动触发

异常还可分为 fault、trap 和 abort。fault 保存的 RIP 通常指向犯错指令，修复后可重试。

C

门描述符位域

P、gate type、selector 和 offset 决定能否跳转以及跳到哪里。

P=0 表示本项无效。

IF 是 RFLAGS.bit9，不是独立寄存器。

  • IF 只控制可屏蔽外部中断，不屏蔽 NMI 或异常。
  • interrupt gate 先把旧 RFLAGS 压栈，再清当前 IF。栈中保存进门前 IF，iretq 可恢复它。
  • trap gate 保持 IF 原值，不强制置 1。

IST 是 3 位索引，不是栈地址。

0 表示不用 IST；1～7 分别选择当前 TSS.IST1～TSS.IST7。TSS.ISTn 保存专用栈的初始 RSP。

操作系统按 handler 的栈可靠性选择：

  • 普通异常通常取 0。
  • 双重故障等“当前栈可能已不可信”的 handler，应评估独立栈。
  • NMI、MC、DB 按各自上下文设计。

非零 IST 在同特权级也会切栈。

D

异常栈帧

是否有 error code、是否切栈，共同决定异常栈帧。

[RSP+0] 表示当前 RSP 指向的内存槽位。+0 是字节偏移，不是槽内数值 0。每格 8 字节，高地址在上方。

x86 栈向低地址增长。 PUSH 先让 RSP 减 8，再把新值写入 [RSP]。后压入的数据地址更低，POP 反向进行。

为什么 x86 的栈向下增长？

这是 x86 ISA 的历史约定，不是速度或安全性上的必然。其他架构不一定这样设计。

一种常见布局是栈放在地址空间高端向下增长，堆和数据从低端向上使用。中间的空闲区由两侧共享，不必为栈和堆各划固定容量。

CPU 依次压入 RFLAGS、CS、RIP。向量有 error code 时，CPU 最后压入它。

只有切栈才额外保存旧 RSP 和旧 SS。特权级变化或非零 IST 都会切栈。同特权级使用非零 IST 也会保存这两项。

CPU 不在运行时猜 error code。 ISA 按向量表规定自动压栈。向量 8、10～14、17、21 带 error code；其它异常、外部中断和软件中断不带。

公共 handler 是多个向量共用的软件代码。判断依据是向量号和入口路径，不是门描述符里的某个标志位。

向量类别 CPU 进门时 入口 stub
8、10～14、17、21 压真实 error code 不补
其它异常 不压 补压 dummy 0
外部中断、软件中断 不压 需要统一布局时补压 dummy 0

真实 error code 可能为 0。 不能靠 [RSP] 的值判断有没有 error code。入口 stub 可再压一个向量号，让公共 handler 知道来源。

这样所有入口共用一种结构体布局。

E

跳转、升级与返回

handler 可以恢复执行，也可以只报告现场后停机。

fault 修复后，iretq 从保存的 RIP 继续。

真实 error code 由 CPU 自动压栈。dummy 0 由软件入口 stub 手动压栈。

自动压栈不等于 iretq 自动出栈。 iretq 不会自动弹出真实 error code，也不会弹出 dummy 0。

软件返回前按布局恢复 RSP。典型情况先跳过 8 字节，再执行 iretq。若还有附加数据，按实际布局处理。

查表失败或 handler 再次出错会让异常升级。连续升级会导致 triple fault 和 CPU 复位。

H

自测

1. 某向量没有 error code，公共 handler 却要求统一帧布局。入口应做什么？

  • A. 不压任何数据，让 handler 猜测
  • B. 补压一个占位 0，再压向量号
  • C. 把 RIP 改成 error code
  • D. 改用 trap gate
第 1 题答案与解析

B。占位 0 让有无 error code 的入口共用同一布局。

2. ring3 进入 ring0 handler 时，栈帧比同特权级多哪两项？

  • A. 旧 SS 和旧 RSP
  • B. RAX 和 RBX
  • C. CR2 和 CR3
  • D. GDTR 和 IDTR
第 2 题答案与解析

A。特权级切换需要记录返回时的栈，因此多保存旧 SS/RSP。

3. handler 尚未执行完时，要允许另一个可屏蔽中断抢占它，哪种门更直接？

  • A. interrupt gate，因为它清 IF
  • B. trap gate，因为它保留 IF
  • C. 任意门，因为 IF 与门无关
  • D. P=0 的门
第 3 题答案与解析

B。trap gate 保留 IF。若进门前 IF=1，handler 中仍可响应可屏蔽中断。interrupt gate 进门清 IF，但可在安全保存现场后执行 sti。trap gate 不强制开 IF，也不控制 NMI。

4. fault 的问题已经修复，想重试原指令，应选择什么？

  • A. 直接 ret
  • B. 再次触发同一异常
  • C. 清理入口数据后 iretq 到保存的 RIP
  • D. 把 P 位清零
第 4 题答案与解析

C。fault 保存的 RIP 指向原指令，iretq 可恢复执行。

5. 公共 handler 读到 error code 槽位的值为 0，能否断定它是软件补的 dummy 0？

  • A. 能，真实 error code 一定大于 0
  • B. 能，CPU 从不压入数值 0
  • C. 不能，真实 error code 可能为 0，要按向量和入口判断
  • D. 能，只要门是 interrupt gate
第 5 题答案与解析

C。真实 error code 可能为 0。公共 handler 只有结合向量号或入口路径，才能区分真实 0 与 dummy 0。
