# Phase 1 · Linux 0.11 自顶向下拆解

模块划分总图：`docs/arch/original.svg`（源码 `original.d2`）

## 模块清单（职责 / 输入 / 输出 / 接口契约）

### boot（bootsect.s → setup.s → head.s，~700 行汇编）
- 职责：接力开机。bootsect 被 BIOS 加载到 0x7C00，把自己挪到 0x90000 并读入 setup + 内核主体；setup 收集硬件信息（内存大小、硬盘参数）、把内核挪到 0x0、开 A20、设临时 GDT/IDT、切保护模式；head.s 建正式页表（4 张页表恒等映射 16MB）后跳进 main()。
- 输入：BIOS 中断服务、磁盘扇区。输出：一个分页已开启、跳到 `init/main.c:main()` 的 32 位保护模式环境。
- 契约：完成后 CPU 处于保护模式+分页态，中断关闭，内存布局固定（内核在 0x0，启动参数在 0x90000 页）。

### init/main.c（212 行）
- 职责：总编排。依次调 mem_init / trap_init / blk_dev_init / chr_dev_init / tty_init / time_init / sched_init / buffer_init / hd_init / floppy_init，开中断，move_to_user_mode，fork 出 init 进程。
- 契约：每个 xxx_init() 把一个子系统从"不可用"带到"可被系统调用使用"；main 返回后 0 号进程永久 `for(;;) pause()` 当 idle。

### 内核核心（sched.c 412 / fork.c 152 / exit.c 196 / signal.c 119 / traps.c 208 / system_call.s 285 行）
- 职责：进程生命周期（fork/exit/wait）、调度（schedule + sleep_on/wake_up）、信号、CPU 异常注册、系统调用分发。
- 输入：int 0x80（用户态系统调用，eax=调用号，共 74 个）、IRQ0 时钟中断（100Hz）、CPU 异常（0~16 号）。输出：进程切换、信号投递、panic。
- 契约：`task[64]` 全局任务表是唯一进程注册中心；`current` 指向当前进程；调度只发生在时钟中断/主动 sleep；上下文切换用 TSS 硬件机制（`switch_to` 宏，sched.h:173）。

### mm 内存管理（memory.c 431 / page.s）
- 职责：物理页分配（mem_map 字节数组，一页 4KB）、页表复制/释放、缺页处理（do_no_page 按需加载 / do_wp_page 写时复制）。
- 输入：fork 时的 copy_page_tables、#14 缺页异常、系统调用 get_free_page。输出：物理页、页表项。
- 契约：主内存从 buffer 末尾到 memory_end，按 4KB 页管理；每进程固定 64MB 线性地址槽（槽号=任务号），共享一张页目录。

### fs 文件系统（17 个文件，~4.6k 行）
- 职责：MINIX 1.0 文件系统全实现：super（超级块/挂载）、inode（文件元数据）、namei（路径解析）、open/read_write/fcntl/ioctl/stat（文件操作系统调用）、buffer.c（块缓冲缓存）、exec.c（加载可执行文件）、pipe（管道）。
- 输入：sys_* 系统调用、buffer cache 返回的磁盘块。输出：文件数据、inode 操作结果。
- 契约：一切块 IO 必须经过 buffer.c（bread/bwrite），禁止直接调驱动；inode/file/super_block 三级结构是全部文件操作的状态载体。

### blk_drv 块设备驱动（ll_rw_blk.c / hd.c 349 / floppy.c / ramdisk.c）
- 职责：ll_rw_blk 维护统一请求队列（电梯排序合并）；hd/floppy 各自把请求翻译成硬件命令并处理完成中断。
- 输入：buffer cache 提交的读写请求（ll_rw_block）。输出：扇区数据 + 完成中断唤醒等待进程。
- 契约：上层只调 ll_rw_block(READ/WRITE, buffer)，不知道也不关心是硬盘还是软盘。

### chr_drv 字符设备驱动（tty_io.c 350 / console.c 710 / kb.S 588 / serial.c）
- 职责：tty 层做行规程（缓冲、回显、规范模式）；console 直接操作 VGA 显存写屏；kb.S 处理键盘中断把扫描码变 ASCII。
- 输入：IRQ1 键盘中断、用户 write()。输出：tty 缓冲（供 read）、VGA 显存（可见字符）。
- 契约：用户进程面对的就是 /dev/tty，read/write 语义与文件一致（万物皆文件的雏形）。

### lib（12 个文件）
- 职责：内核自用的 C 库子集：string.c、系统调用内联封装（open/write/close/dup/execve/wait/_exit 等）。
- 契约：纯工具，被所有模块调用，自己不调别人。

## 关键架构决策卡片

### 卡片 1 · 单内核：所有模块住 ring 0，模块间直接函数调用
- **决策点**：内核各子系统跑在同一个地址空间、同一个权限级，互相直接 call；还是拆成独立服务进程，靠消息通信？
- **备选**：(a) 单内核（所选）；(b) 微内核（MINIX 方案，文件系统/驱动是用户态服务，靠 IPC）。
- **选择理由**：1991 年的 i386 上一次进程间消息往返要经过两次特权级切换，文件读一次要穿三四个服务；单内核一次函数调用搞定。代码也简单——没有 IPC 层、没有服务间协议。
- **放弃的成本**：微内核的容错性没要到——任何模块（比如 floppy 驱动）一个野指针就能 panic 全系统，Linux 后来三十年的驱动 bug 史就是这笔账；模块化隔离也没要到——不能在运行时换掉文件系统实现而不重启。
- **失效边界**：当系统需要跑不可信第三方驱动、或要求部分崩溃可热恢复（电信设备、车载）时，这个决策就该被质疑——这正是 seL4、Fuchsia 出现的场景。

### 卡片 2 · 每进程一个固定 64MB 段槽位，全系统共享一张页目录
- **决策点**：进程地址空间怎么隔离？0.11 用 i386 段式：任务 n 的 LDT 把线性地址 [n×64MB, (n+1)×64MB) 划给它，页目录只有一张、内核恒等映射其中。
- **备选**：(a) 段槽位 + 共享页目录（所选）；(b) 每进程独立页目录、段基址全 0（Linux 0.95 之后至今的方案）。
- **选择理由**：fork 时子进程地址天然落在另一个槽，copy_page_tables 只需把父进程那段页表项复制到子进程对应区间，代码极少；内核代码永远能直接访问任意进程的线性地址（槽位可算），copy_to_user 几乎免费。
- **放弃的成本**：可扩展性没要到——任务数硬上限 64、单进程硬上限 64MB，写死在地址布局里；每进程独立页表带来的隔离粒度也没要到（比如不同进程同一线性地址映射不同物理页这种现代基本功，0.11 做不到，靠段槽错位硬扛）。
- **失效边界**：进程数或内存需求一超上限，此设计立刻死。Linus 自己在 0.95 就推翻了它——这是"为了第一版能跑起来而赌硬件特性"的典型，赌的是"我重写得够快，上限就不是问题"。

### 卡片 3 · buffer cache 是块设备 IO 的唯一通道
- **决策点**：文件系统怎么读盘？0.11 规定一切块读写走 buffer.c：hash 表查缓存 + 空闲链表 LRU 回收 + 脏块延迟写回。
- **备选**：(a) 统一 buffer cache（所选）；(b) 每次 IO 直接读盘；(c) 每个文件/每个驱动各自缓存。
- **选择理由**：磁盘比内存慢约 4 个数量级，目录项、inode 块被反复读，缓存命中率决定系统快慢；统一缓存让"同一个块被两个进程读"自动去重。
- **放弃的成本**：(b) 的延迟确定性没要到——数据库类负载想要"我知道这次写真的落盘了"，buffer cache 的延迟写回意味着 sync 之前数据都在内存里赌不宕机；(c) 的按文件定制策略也没要到（比如大文件顺序读污染缓存，0.11 没有回收保护）。
- **失效边界**：需要 IO 确定性（数据库 WAL）或内存大到缓存策略比"有没有缓存"更重要时——现代 Linux 的 page cache + O_DIRECT + cgroup IO 控制就是在这条边界上演化出来的。

### 卡片 4 · 用 i386 TSS 硬件机制做任务切换
- **决策点**：上下文切换怎么实现？0.11 直接 `ljmp` 到目标任务的 TSS 描述符，CPU 自动保存/恢复全部寄存器（sched.h:173 的 switch_to 宏）。
- **备选**：(a) TSS 硬件切换（所选）；(b) 软件切换：手动 push/pop 寄存器、换栈、换页表。
- **选择理由**：代码只有几行汇编，Linus 赌"x86 给了硬件机制就是让人用的"；省掉了手写寄存器保存清单的正确性风险。
- **放弃的成本**：可移植性整个没要到——TSS 切换是 x86 独有，后来 Linux 移植到任何新架构都得重写成软件切换；而且实测硬件切换并不比软件快（CPU 每次无条件保存全部状态，包括用不到的），Linux 2.x 起全面转向软件切换，这个"硬件福利"最终被证明是弯路。
- **失效边界**：要移植、或上下文里出现硬件 TSS 装不下的状态（扩展浮点/向量寄存器）时。教训：硬件给的机制不一定是好机制，"代码少"的账要算上未来的移植成本。

### 卡片 5 · fork 写时复制（COW）
- **决策点**：fork 复制进程时，物理内存页复制不复制？0.11 不复制：父子共享物理页，双方页表项都标只读，谁第一个写，谁触发 #14 缺页，do_wp_page 才真正复制那一页。
- **备选**：(a) COW（所选）；(b) fork 即全量复制（早期 Unix 做法）。
- **选择理由**：shell 跑命令是 `fork` 后立刻 `exec`，旧地址空间整个丢弃——全量复制几乎 100% 是白干；COW 让 fork 从 O(内存量) 变成 O(页表项数)。
- **放弃的成本**：(b) 的行为简单性没要到——COW 引入了缺页异常这条异步路径，fork 之后内存占用变成"随写入逐渐增长"，父进程写自己原来的数据也可能触发分配，内存耗尽从"fork 时就知道"变成"运行中随时可能爆"。
- **失效边界**：几乎没有——这个赌注赢了三十年，至今所有主流 OS 都在用。算是五张卡里唯一没被推翻的。

## 概念词汇表（首次速览，里程碑里用到再展开背景卡片）

| 概念 | 一句话（大白话） |
|---|---|
| 内核态 / 用户态（ring 0 / ring 3） | CPU 的两个权限档。用户态跑普通程序，碰不了硬件和别人内存；内核态无所不能。切换靠"门"，不能随意跳 |
| 系统调用 | 用户程序求内核办事的唯一正规渠道：`int 0x80` 软中断，eax 放事号 |
| 中断 vs 异常 | 中断是硬件从外面敲门（时钟、键盘、磁盘完事）；异常是 CPU 执行指令时自己摔了（除零、缺页） |
| 进程 / task_struct | 一个正在跑的程序 = 一张 task_struct 登记表：状态、优先级、打开的文件、内存段、信号，全在上面 |
| GDT / LDT | CPU 的两张"段通行证表"：GDT 全局一张，LDT 每进程一张，段寄存器里存的是表索引 |
| 分页 / 页表 | 把内存切成 4KB 一页，页表登记"哪个线性页对应哪个物理页"；隔离和保护都靠页表项上的权限位 |
| TSS | i386 给每个任务准备的一张寄存器存档表，硬件任务切换用的 |
| buffer cache | 磁盘块的内存缓存，文件系统读盘的唯一通道 |
| inode | 文件的"户口本"：大小、权限、数据块门牌号，不含文件名（文件名在目录项里） |
| tty | 终端设备的抽象：键盘进、屏幕出，中间有缓冲和行编辑 |

## 本阶段推断但未从代码确认的内容
- 无重大推断。模块清单、边、74 个系统调用、100Hz 时钟、TSS 切换、COW 均已核对源码（sched.h / system_call.s / traps.c / sched.c / main.c）。MINIX 文件系统的盘上格式细节（inode 位图、块位图布局）尚未逐字节核对，Phase 2/3 到 fs 里程碑时现场确认。

## 对我们 Rust 重写的预告（Phase 2 详议）
- boot 段是 16 位实模式汇编，Rust 编译器不支持——候选：① 保留极简汇编 boot 只做到进保护模式（贴近原版）② 用 GRUB/multiboot 直接引导进 32 位（Rust OS 社区标准做法）。Phase 2 出决策卡。
- 原版"段槽位"设计在 Rust 里复刻没有语言障碍（都是页表操作），但是否照抄架构，Phase 2 按铁律 9 决定。
