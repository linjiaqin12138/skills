# HHDM：高半区直接映射

> 概念深读（M3 Bite1 背景卡片承诺）。面向知道分页、但不知道 HHDM 是什么的读者。
> 读完你应能回答：HHDM 是什么；它在虚拟地址空间里占哪一段；为什么运行时改页表离不开它。

> 交互版（推荐）：[figures/hhdm/index.html](figures/hhdm/index.html)

## 一句话版本

**HHDM**（Higher Half Direct Map，高半区直接映射）是启动加载器在虚拟地址空间里划出的一段区间。窗口里的每个虚拟地址都指向同一个偏移的物理地址：

```
虚拟地址 = 物理地址 + HHDM 偏移
```

本项目的偏移由 Limine 给出，典型值是 `0xFFFF800000000000`。同一块物理内存因此有两个虚拟地址，随便挑一个用。

## 它长什么样

假设 RAM 覆盖物理 `0x0`–`0x8000_0000`：

| 物理地址 | HHDM 虚拟地址 | 这是什么 |
|---|---|---|
| `0x0010_0000` | `0xFFFF800000100000` | 内核镜像的起点 |
| `0x0022_1000` | `0xFFFF800000221000` | PML4，CR3 指向的那张表 |
| `0x0022_3000` | `0xFFFF800000223000` | BSS 里的静态页表 `EXTRA_PAGE_TABLES[0]` |
| `0xFEE0_0000` | `0xFFFF8000FEE00000` | LAPIC 寄存器区（设备，不在 RAM 里） |

前三行是 HHDM 真正帮上忙的地方。最后一行是个陷阱：地址落在 HHDM 窗口<b>之内</b>，可那一段不是 RAM，没有任何映射。

## 为什么需要它

矛盾只有一句话：**CPU 查页表用物理地址，Rust 指针是虚拟地址。**

想改页表，得先找到那张表。它躺在物理内存里，比如 PML4 在物理 `0x221000`。手上只有物理地址，写不进去。HHDM 给出解法：物理内存已被原样搬到虚拟空间的高半区，任何物理地址因此都自带一个能解引用的孪生地址。加一次偏移，矛盾消失。

本项目用它做两件事：

1. **读写页表。** `entry_ptr = hhdm_offset + table_physical + index * 8`，指针由此而来（`impl/kernel/src/lapic.rs:162`、`:181`）。
2. **把 BSS 里静态页表的虚拟地址换算成物理地址。** 公式是 `table_virtual - kernel_virtual + kernel_physical`（`impl/kernel/src/lapic.rs:169`）。

## 和「内核镜像在高半区」不是一回事

同一块物理内存，在虚拟空间里有两个家：

| | 位置 | 谁在用 |
|---|---|---|
| 内核镜像 | `0xFFFF_FFFF_8000_0000` | 内核按链接好的符号访问自己的变量和代码 |
| HHDM 窗口 | `0xFFFF_8000_0000_0000` | 手上只有物理地址时，按物理地址一一对应地访问 |

HHDM 解决的是「我手上只有物理地址，怎么写它」。内核镜像解决的是「我怎么访问自己的代码和数据」。两件事，各管一头。

## 常见误解

| 常见以为 | 实际 |
|---|---|
| HHDM 覆盖整个 4 GiB 地址空间 | 只覆盖 RAM。设备区在窗口内，但没被映射 |
| 有了 HHDM 就不用管页表了 | 改页表本身离不开 HHDM；设备页还得自己补映射 |
| HHDM 里的地址和内核镜像地址是一回事 | 两套映射，位置和用途都不同 |
