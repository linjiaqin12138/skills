# 0001 中断上下文只做最小工作

- 状态：起草
- 来源：手搓
- 出现于：m03-b01
- 被取代于：

起草可以改。用户确认这一课之后，手搓决定改为「已采纳」。用户确认 Phase 1 之后，原项目决定改为「已记录」。此后不改正文。要推翻，新开一篇，本篇状态改为「被取代」，并填上新编号。

## 上下文

M3 Bite1 引入 LAPIC 定时器中断。`printk!` 的全局 console 在 M2 仍是 `static mut`，如果中断 handler 在主流程打印途中再次打印，会重入并破坏光标状态。定时器还需要尽快完成并 `iretq`，让被中断的内核继续运行。

## 备选

1. handler 每次中断直接 `printk!`：演示路径短，但必须先把 console 换成可重入或带中断屏蔽的锁，并延长关中断时间。
2. handler 只把 `jiffies` 原子计数加一并发送 LAPIC EOI；主流程观察计数并打印：本 Bite 不需要 console 锁，中断停留时间短。

## 决定

选方案 2。IRQ32 handler 只执行 `AtomicU64::fetch_add` 与 LAPIC EOI，随后恢复寄存器并 `iretq`。主流程在普通上下文读取原子计数，每累计 100 tick 输出一行。键盘回显需要在中断上下文打印时，再在 M3 后续 Bite 收敛 D15。

## 放弃的成本

方案 1 不需要主流程的计数观察循环，演示代码更直接，而且能立即证明 handler 执行过。我们放弃了这份简单，换来不中断打印路径和更短的关中断窗口。

## 失效边界

tick 内需要执行调度、睡眠唤醒或设备 I/O 时，不能再只做计数；应引入明确的下半部/调度路径，并重新评审锁与中断关闭时长。若未来 console 已可安全重入，也仍需单独评估长时间格式化输出是否适合放在 IRQ handler。
