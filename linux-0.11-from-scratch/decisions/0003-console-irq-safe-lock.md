# 0003 console 用关中断临界区收敛 D15

- 状态：起草
- 来源：手搓
- 出现于：m03-b02
- 被取代于：

起草可以改。用户确认这一课之后，手搓决定改为「已采纳」。用户确认 Phase 1 之后，原项目决定改为「已记录」。此后不改正文。要推翻，新开一篇，本篇状态改为「被取代」，并填上新编号。

## 上下文

M3 Bite2 键盘 handler 要在中断上下文 `printk!` 回显。M1 起全局 console 是 `static mut`，主流程打印途中若被键盘中断打断再打印，会重入并破坏光标。D15 预定在本 Bite 收敛。

## 备选

1. handler 只把扫描码丢进无锁环形缓冲，主流程取出再打印：中断路径不碰 console，可继续推迟 D15，但本 Bite 验收要证明「中断上下文能安全打印」，且会把回显延迟到主循环。
2. 用关中断临界区包住 console 的 `_print` / `init`：拿锁前 `cli`（或读 `rflags` 再清 IF），释放时按进入时的 IF 恢复。单核下阻止重入，实现短。
3. 引入可睡眠互斥或带中断嵌套计数的完整自旋锁库：语义更全，但当前无多核、无阻塞、无下半部，成本过高。

## 决定

选方案 2。`printk!` 与 console 初始化走同一把「关中断 + 独占」锁；键盘 handler 与主流程（含 jiffies 打印）都经此路径。中断门进门时 IF 已清，handler 内再拿锁是可重入的嵌套关中断，释放时不得错误地把 IF 打开。

## 放弃的成本

方案 1 中断停留更短、本 Bite 可以少改 console，我们放弃这份简单，换来按 STATE 承诺收敛 D15，并直接演示中断上下文打印。方案 3 以后多核或可睡眠路径更省事；我们放弃这份超前完备，避免在单核阶段引入用不到的锁协议。

## 失效边界

出现多核、或 console 持锁期间需要开中断等待（磁盘、睡眠），关中断独占不再够用，应换成按核的自旋锁或明确的下半部打印路径。
